# S4-D2-R2 基线状态监督实验计划

## 先看结论

下一步仍然不是强化学习，而是做一次更容易解释的监督学习实验：让神经网络在
传统控制器实际经过的状态上学习“此时还应该补多少高阶像差”。

旧模型像是只看过“老师开车时的路况”，一旦自己接管方向盘，走到没见过的路段就
不断犯错。本实验先让它看“传统控制器开车时真实遇到的路况”。如果这样仍学不好，
就说明问题不只是训练数据来自错误轨迹；如果离线预测明显变准但闭环仍失败，再考虑
一次有限的“学生自己走过的状态”数据聚合。当前不授权这一步。

## 这次只改变什么

| 项目 | 旧实验 | 本实验 |
|---|---|---|
| 训练时看到的状态 | 理想教师自己产生的轨迹 | 传统控制器产生的基线轨迹 |
| 要预测的答案 | 两帧后的新增11维理想修正 | 相同答案 |
| 输入 | 连续4帧、共210个数 | 不变 |
| 神经网络 | 两层、每层256个神经元 | 不变 |
| 输出 | 新增11维动作 | 不变 |
| 动作限制 | 每维不超过0.05 rad | 不变 |
| 主要科学门槛 | 桶内功率至少提高2% | 不变 |

这样设计的目的，是把“换训练数据”和“换算法”分开。实验成功或失败时，才能知道
原因来自哪里。

## 数据怎么生成

传统控制器先在动态湍流中运行。每一步保存它当前能看到的4帧历史，再利用仿真器中
两帧后的真实扰动计算正确的新增11维标签。未来真实扰动只用于制作答案，不放进模型
输入。

正式数据按完整回合拆分：

| 数据 | 每个条件和硬件档位的回合数 | 样本数 | 用途 |
|---|---:|---:|---|
| 训练集 | 32 | 115200 | 更新网络参数 |
| 验证集 | 16 | 57600 | 早停和选择最佳检查点 |
| 诊断测试集 | 16 | 57600 | 比较旧模型和新模型 |

同一回合不会跨数据集。正式测试继续覆盖3类湍流和6种仿真硬件误差档位。

## 训练和闭环比较

新模型沿用初始化种子 `8201、8202、8203`，便于与三个旧模型一一配对。训练完成后，
在同一批新测试回合上比较：

- 旧的岭回归和三个旧神经网络；
- 新的岭回归和三个新神经网络；
- 每个模型固定使用10%、25%和50%三档动作；
- 50%是预先指定的主要档位，不能看完结果后临时挑一个最好档位。

正式评估计划产生432条场景汇总、6912条回合记录和完整分时段遥测。

## 怎样才算成功

必须同时满足：

1. 三个新神经网络的离线预测都通过原有可学习门槛；
2. 每个新模型的测试误差不超过对应旧模型的一半；
3. 在50%主要动作档位，三个新模型都通过原2%闭环门槛；
4. 每个新模型相对对应旧模型的桶内功率增益至少再提高2个百分点；
5. 六个硬件误差档位、Strehl比、残差相位和违规率也全部满足原门槛。

如果只满足前两项，说明训练数据方向正确，但还不足以安全闭环。此时先审计结果，
再决定是否允许一次学生状态数据聚合，不自动改算法、不自动开始强化学习。

## 用户怎样运行

助手已经完成正式预检和CUDA快速冒烟。正式训练只能由用户在IDE集成终端启动：

```powershell
.\.venv\Scripts\python.exe scripts\train_s4_baseline_state_imitation.py --config configs\experiments\s4_baseline_state_imitation_v1.yaml
```

终端会显示当前阶段、训练步数、平均损失、预计剩余时间和CUDA显存，同时写入
`progress.jsonl`。运行结束后只需告诉助手“基线状态监督训练完成”，由助手只读检查
结果。不要自行重跑，也不要开始学生状态聚合、强化学习、S4-D3或真实SLM操作。
