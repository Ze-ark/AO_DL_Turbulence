## 一句话说明

上一次实验说明“每次最多微调0.0125 rad”太小。本实验不训练强化学习，而是
让能看到未来仿真答案的理想控制器依次尝试更大的微调范围，找出跨过原2%门槛
至少需要多大的动作。

## 小白版比喻

把传统控制器想成负责转方向盘的主驾驶，强化学习只负责在旁边做小修正。R1
只允许它每次最多修正0.0125 rad。正式理想上限即使“提前知道弯道”，也只提高
0.9602%，说明问题可能不是不会开，而是允许动方向盘的幅度太小。

现在固定车辆、道路和主驾驶，只逐级放宽这个小修正范围：

| 档位 | 每个模态的最大残差动作 |
|---|---:|
| 1 | ±0.0125 rad |
| 2 | ±0.01875 rad |
| 3 | ±0.025 rad |
| 4 | ±0.03125 rad |
| 5 | ±0.0375 rad |
| 6 | ±0.05 rad |

0.0125 rad是R1锚点，0.05 rad是原S4-D2锚点。无论扫描哪个档位，传统控制器
与强化学习合成后的最终单帧变化仍不得超过0.15 rad。

## 实验保持不变的内容

- 冻结传统控制器仍是`tracking_conservative`；
- 观测、10维动作、延迟、量化、稳定时间、配准误差和噪声不变；
- 三类动态、六个硬件误差档位和每个场景16个完整回合不变；
- 未来真值预见仍为0—6帧；
- 桶内功率至少提高2%，同时Strehl、残余相位和违规率门槛也必须通过；
- 正式回合使用2600000段全新种子，2700000段留给未来算法实验。

只有残差动作范围会改变，因此结果可以回答“动作幅度是否限制了容量”，不能
回答“哪种强化学习算法最好”。

## 为什么使用累积包络

对每个动作档位，程序先在0—6帧预见时域中为每个回合挑选桶内功率最高的
结果。随后再做一次从小到大的累积选择：例如检查0.025 rad时，允许从
0.0125、0.01875和0.025 rad三个结果中逐回合选择最好者。

这样做有两个作用：

1. 较大的允许范围在理论上包含较小范围，不会因单个固定档位偶然变差而漏判；
2. 记录“第一次完整通过门槛的最大允许范围”，作为最小已展示动作范围。

这是故意偏乐观的事后选择，不是可部署控制器，更不是数学全局最优。

## 通过规则

某个累积动作范围只有同时满足以下条件才算PASS：

- 全部288个“回合×硬件档位”的总体结果通过原完整门槛；
- 六个硬件档位各自都通过原完整门槛；
- 真值轨迹对齐误差不超过`1e-6`；
- 没有训练、旧轨迹、S4-D3或真实SLM访问。

第一个PASS档位只是“最小已展示范围”，不是精确物理阈值。若六个档位全部
FAIL，只能说明在预声明的0.05 rad以内尚未展示出2%容量。

## 运行规模与输出

正式实验包含18个“物理动态×硬件档位”，总计774个带进度的轨迹组。同一台
GPU上可按上次144个轨迹组约405.5秒粗略估计为约36分钟，但实际时间以进度条
为准。

| 输出 | 用途 |
|---|---|
| `summary.json` | 每个范围的总体、六档位门槛和最小通过范围 |
| `scenario_records.csv` | 每个具体场景、预见时域和动作范围的指标 |
| `progress.jsonl` | 实时完成数、场景、功率与用时 |
| `effective_config.json` | 本次实际采用的参数 |
| `source_manifest.json` | 运行时源码哈希 |

## 运行方法

助手只负责预检与CUDA快速冒烟。正式扫描由用户在IDE集成终端启动：

```powershell
.\.venv\Scripts\python.exe scripts\run_s4_r1_action_range_sweep.py --config configs\experiments\s4_r1_action_range_sweep_v1.yaml
```

运行结束后告诉助手“`理想动作范围扫描完成`”。不要删除输出、重跑、开始R2
训练或打开S4-D3；必须先只读审计。

## 结果之后怎么走

- 若找到通过范围：先审计，再在该范围内设计R2算法和新的训练种子；
- 若0.05 rad仍未通过：不盲目更换RL算法，先重新审视控制结构、动作参数化和
  2%研究假设；
- 无论结果如何，本实验都不授权真实SLM动作或S4-D3。

## 证据边界

这是使用仿真真值的纯CUDA乐观诊断，不是强化学习训练，不代表两台
`FSLM-2K73-P04`、真实双SLM闭环或自然大气性能。
