## 用小白语言理解

把RL策略想成一个给传统控制器“加一点修正”的助手。现在我们知道它加完以后效果更差，但还不知道为什么。诊断会把同一个模型的建议改成五种力度：

| 诊断动作 | 小白解释 | 想回答的问题 |
|---|---|---|
| 0% | 完全不听RL，只用传统控制器 | 程序接线是否正确 |
| 25% | 只采用RL建议的四分之一 | RL是不是用力过猛 |
| 50% | 只采用一半建议 | 中等力度是否更合适 |
| 100% | 原样采用RL建议 | 能否复现R2负结果 |
| 反向100% | 把RL建议方向完全反过来 | RL是不是学反了方向 |

21维和36维都会做同样的检查，并使用相同的新湍流回合，保证比较公平。

## 还会记录什么

每一步不只记录最终功率，还会区分：

1. 模型原本想输出多大的动作；
2. 缩放以后请求了多大的动作；
3. 总动作能量限制是否把请求缩小；
4. 与传统动作相加后，安全范围是否再次改写动作；
5. 环境最后实际执行的动作；
6. 桶内功率、Strehl比、残差相位和违规率。

正式输出会保存逐场景和逐回合CSV，后续审计可以重新计算全部结论。

## 结果怎么判断

| 正式现象 | 暂时支持的解释 | 下一步候选 |
|---|---|---|
| 0%与传统基线不同 | 接线或基线实现有问题 | 先修程序，不训练 |
| 25%或50%转为正增益 | 动作幅度过大 | 重新设计动作尺度后再决定是否训练 |
| 反向100%转为正增益 | 动作方向或符号可能错误 | 检查相位符号和动作映射 |
| 请求动作经常被总能量限制改写 | 策略输出和安全动作空间冲突 | 改动作参数化或约束处理 |
| 所有非零版本仍为负 | 仅缩放和反向无法解释 | 审计后再检查观测、奖励和SAC训练方法 |

这些都是事后诊断线索，不是最终算法优越性结论。正式运行完成后请告诉助手“`S4-D2-R2诊断完成`”，由助手只读审计后再决定是否优化算法。
