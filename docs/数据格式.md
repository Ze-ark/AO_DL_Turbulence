# 数据格式说明

本项目区分静态仿真数据、真实复光场数据、动态监督学习数据和动态控制轨迹。只有动态控制轨迹具备真正的 RL 转移关系。

## 1. 当前静态仿真数据

默认路径：

```text
data/raw_matlab_exports/sim_gaussian_v1.h5
```

状态：

```text
s0_static_physics_validation
```

必需字段：

```text
/input/intensity_turb      湍流光场强度
/input/phase_turb          湍流光场相位
/target/intensity_clean    无湍流高斯目标强度
/target/phase_clean        无湍流高斯目标相位
/meta/frame_id             帧编号
/meta/scene_id             独立场景编号
/meta/random_seed          可复现该场景的随机种子
/meta/turbulence_strength  仿真湍流强度
/meta/r0                    按完整传播路径计算的 Fried 参数
/meta/r0_or_equivalent     为兼容旧 Python 读取器保留，数值与 /meta/r0 相同
```

数组布局支持：

```text
[frame, height, width]     Python 常见格式
[height, width, frame]     当前 MATLAB 导出格式
```

这类数据已通过 S0 物理单元测试，可用于静态监督学习和接口测试；但没有动作造成的下一观测，不能直接作为 RL 数据。

## 2. 当前真实复光场数据

默认路径：

```text
data/real_validation/real_offaxis_2x_validation.h5
```

必需字段：

```text
/input/intensity_turb  真实离轴全息重建复光场强度
/input/phase_turb      真实离轴全息重建复光场相位
/meta/frame_id         原始 PNG 帧编号
/meta/temperature      温差
/meta/crop_rect        频域一阶项裁剪窗口 [x1 y1 x2 y2]
```

真实验证数据没有：

```text
/target/intensity_clean
/target/phase_clean
/action
/next_observation
```

因此它只能用于真实域检查、复场重建验证和影子推理，不能直接计算真实补偿精度，也不能训练闭环 RL。

## 3. 动态纯仿真轨迹

S1 核心环境已经实现，当前策略观测是 22 维特征：10 个残余相位模态、10 个实际加载模态、Strehl 和桶内功率。S2 控制器比较入口现已按下述契约导出封存测试轨迹。当前观测仍是仿真真值模态，必须标记为 `oracle_modal_features`，不能冒充全息重建观测。

动态环境应按“回合—时间步”组织。推荐 HDF5 布局如下：

```text
/observation/intensity        [episode, step, height, width]
/observation/phase            [episode, step, height, width]
/observation/features         [episode, step + 1, feature]
/action/requested_modal       [episode, step, mode]
/action/applied_modal         [episode, step, mode]
/action/applied_phase         [episode, step, height, width]   可选
/metric/reward                [episode, step]
/metric/phase_residual        [episode, step]
/metric/focal_quality         [episode, step]
/metric/action_cost           [episode, step]
/flags/terminal               [episode, step]
/flags/saturated              [episode, step]
/flags/invalid_observation    [episode, step]
/meta/episode_id              [episode]
/meta/step_id                 [episode, step]
/meta/random_seed             [episode]
/meta/r0                      [episode]
/meta/wind_speed              [episode]
/meta/wind_direction          [episode]
/meta/noise_level             [episode]
/meta/delay_frames            [episode]
/meta/simulator_version       文件属性或字符串表
```

时间步 `t` 的 RL 转移定义为：

```text
observation[:, t]
    + applied_action[:, t]
    → reward[:, t]
    + observation[:, t + 1]
```

不必重复保存一份 `next_observation` 图像；同一回合中的下一时间步就是下一观测。最后一步由 `terminal` 标记。

因此观测比动作和指标多一帧：第 `t` 个动作使用 `observation[:, t]`，环境返回的下一观测保存到 `observation[:, t + 1]`。

### 为什么同时保存 requested 和 applied 动作

控制器想要的动作可能因量化、饱和、安全投影或执行器延迟而改变。RL 和系统辨识必须使用真实执行的 `applied_modal`，同时保留 `requested_modal` 用于检查控制器是否频繁越界。

## 4. S2 动态 ResUNet 监督数据

默认路径：

```text
data/processed/s2_dynamic_resunet_v1.h5
```

每个输入样本形状为 `[2, height, width]`：

```text
input[0] = 光瞳内归一化强度
input[1] = 光瞳内包裹后的残余相位
```

HDF5 布局：

```text
/train/input
/train/target_phase
/train/episode_seed
/train/step_id
/validation/input
/validation/target_phase
/validation/episode_seed
/validation/step_id
```

训练集和验证集按完整回合拆分。感知测试集由另一组种子单独生成，不写入这个训练 HDF5；最终控制器比较又使用一组新的封存种子。

这里的二维输入是**无噪声理想瞳面传感器**，不是经过传播和离轴全息重建得到的接收面复场。它用于公平检验模型接口，不能代表真实相机观测。

## 5. S3 多帧动力学监督数据

默认路径：

```text
data/processed/s3_dynamics_train_validation_v1.h5
```

训练文件只包含训练和验证集合，不包含封存测试：

```text
/train/history          [sample, 8, 10]
/train/target           [sample, 10]
/train/episode_seed     [sample]
/train/condition_index  [sample]
/train/target_step      [sample]
/validation/history
/validation/target
/validation/episode_seed
/validation/condition_index
/validation/target_step
```

`history` 是最近 8 帧由“残余模态减去实际加载模态”重建的湍流模态，`target` 是下一帧湍流模态。它仍属于仿真真值诊断数据，不是相机或 ResUNet 观测。

每个样本都保留完整回合种子、条件编号和目标时间步。统计时必须先在同一回合内汇总，再以回合作为独立单位；不能把大量重叠窗口当作相互独立的样本计算置信区间。

数据量诊断使用独立文件：

```text
data/processed/s3_data_scaling_pool_v1.h5
```

包含：

```text
/train_pool/history
/train_pool/target
/train_pool/episode_seed
/train_pool/condition_index
/train_pool/target_step
/validation/...
```

`train_pool` 一共包含384个完整回合。48、96、192和384回合子集按六个物理条件均衡选择，并在每种物理条件的两批独立种子间等量取样；不能直接对窗口随机抽样。该文件使用新的开发种子，属性 `original_sealed_test_included=false`，不能与原S3封存测试混合。

后续128/256维收敛复查复用同一个HDF5，不生成第二份数据。程序必须先核对上游 `summary.json` 中记录的SHA-256哈希。结果额外保存 `condition_records.csv` 和 `condition_summary.csv`，按未见风速、风向分别记录GRU误差、岭回归误差和技能分数。

S3-B复杂动态门槛使用新的独立文件：

```text
data/processed/s3_complex_dynamics_v1.h5
```

它仍使用相同的 `history`、`target`、`episode_seed`、`condition_index` 和 `target_step` 字段，但含义更严格：

- `history`：最近8帧可带高斯观测噪声的oracle湍流模态；
- `target`：两帧之后的无噪声oracle湍流模态；
- `conditions_json`：记录动态类型、沸腾系数、基础风速/风向、变风幅度与周期、观测噪声和种子；
- 文件属性 `prediction_horizon_frames=2`；
- 文件属性 `original_sealed_test_included=false` 和 `s3b_sealed_test_included=false`。

训练、验证和S3-B封存条件使用互不重叠的新完整回合种子。正式训练文件只写入 `train` 和 `validation` 两组，不生成封存数据。训练目标中的“无噪声”只用于纯仿真系统辨识门槛，不能冒充真实相机真值。

封存测试由独立评估脚本在模型冻结后生成，并写入：

```text
outputs/s3_dynamics_v1/sealed_test/sealed_test_data.h5
```

## 6. S4-A线性闭环开发轨迹

正式S4-A轨迹写入：

```text
outputs/s4_linear_robustness_v1/trajectories/
```

每个文件对应“一个控制器×一个开发条件×32个完整回合”。关键字段为：

```text
/observation/features       [episode, step + 1, 22]
/observation/true_features  [episode, step + 1, 22]
/action/requested_modal     [episode, step, 10]
/action/applied_modal       [episode, step, 10]
/metric/strehl              [episode, step]
/metric/power_in_bucket     [episode, step]
/metric/phase_residual_rmse [episode, step]
/metric/action_cost         [episode, step]
/metric/violation_fraction  [episode, step]
/meta/episode_seed          [episode]
```

`features` 是控制器实际看到的观测：只有残余模态通道加入条件指定的高斯噪声；`true_features` 是同一时刻的无噪声仿真观测，用于审计。Strehl、桶内功率和残余相位误差始终由环境真值计算，不能用带噪观测反算后冒充独立指标。

文件属性必须记录 `stage=S4-A`、条件名称、动态类型、观测噪声、两帧延迟和实验配置。正式入口只导出开发轨迹；S4封存条件只登记，不生成文件。快速冒烟不导出轨迹，也不能用于正式结论。

S4-B第一次正式运行后写入：

```text
outputs/s4_sealed_validation_v1/SEALED_TEST_OPENED.json
outputs/s4_sealed_validation_v1/source_manifest.json
outputs/s4_sealed_validation_v1/trajectories/
```

轨迹字段与S4-A相同，但文件属性必须为 `stage=S4-B` 和 `sealed_test=true`。只允许出现“不校正”和冻结泄漏积分器两类控制器，共12个轨迹文件。`SEALED_TEST_OPENED.json` 在第一条轨迹前写入；即使运行中断也不得删除后重跑。`source_manifest.json` 保存封存前冻结的运行代码SHA-256哈希。

### S4-C0硬件误差轨迹扩展

S4-C0沿用S4-A/S4-B字段，并增加以下逐步数据：

```text
/action/delayed_modal             [episode, step, 10]
/action/registered_modal          [episode, step, 10]
/metric/measured_power_in_bucket  [episode, step]
/metric/saturated_fraction        [episode, step]
/metric/slew_limited_fraction     [episode, step]
/metric/settling_limited_fraction [episode, step]
/timing/action_latency_ms         [step]
```

`delayed_modal` 是延迟队列输出，`registered_modal` 是加入坐标错位后的动作，`applied_modal` 才是最终实际动作。三者不能混用。`measured_power_in_bucket` 模拟光功率计噪声；独立科学指标仍使用无噪声的 `power_in_bucket`，不得用带噪读数替换真值评价。`action_latency_ms` 是整个CUDA回合批次每个时间步的一次控制器计算耗时，不是每个回合各自的独立耗时。

正式输出还必须包含：

```text
outputs/s4_hardware_stress_v1/RUN_STARTED.json
outputs/s4_hardware_stress_v1/source_manifest.json
outputs/s4_hardware_stress_v1/trajectory_manifest.json
outputs/s4_hardware_stress_v1/summary.json
outputs/s4_hardware_stress_v1/profile_summary.csv
outputs/s4_hardware_stress_v1/condition_summary.csv
outputs/s4_hardware_stress_v1/progress.jsonl
```

`trajectory_manifest.json` 保存每个HDF5轨迹文件的SHA-256。快速冒烟不创建上述目录，不能当成正式数据。

### S4-D0与S4-D1鲁棒控制轨迹

S4-D0和S4-D1沿用S4-C0全部逐步字段，特别是请求动作、延迟动作、配准后
动作与实际加载动作必须分别保存。S4-D0文件属性为 `stage=S4-D0`；S4-D1
文件属性必须包含：

```text
stage=S4-D1
unseen_validation=true
retuning_allowed=false
assumed_hardware_parameters_not_h1_measurements=true
```

S4-D1只允许3个控制器、7个硬件档位和3个未见物理条件，共63个HDF5
轨迹。每个控制器—档位包含96个完整回合；同一档位的三种控制器必须
共享相同回合种子，所有S4-D1种子必须与S4-C0和S4-D0隔离。

正式输出必须包含：

```text
outputs/s4_robust_controller_validation_v1/UNSEEN_VALIDATION_OPENED.json
outputs/s4_robust_controller_validation_v1/source_manifest.json
outputs/s4_robust_controller_validation_v1/trajectory_manifest.json
outputs/s4_robust_controller_validation_v1/summary.json
outputs/s4_robust_controller_validation_v1/controller_profile_summary.csv
outputs/s4_robust_controller_validation_v1/condition_summary.csv
outputs/s4_robust_controller_validation_v1/progress.jsonl
outputs/s4_robust_controller_validation_v1/trajectories/
```

打开标记必须在第一条未见轨迹前写入；即使运行中断或门槛FAIL，也不能
删除目录重跑。D1只做冻结验证，不允许输出新的候选排名。

## 7. 数据拆分规则

- 静态数据按独立湍流场景和随机种子拆分，不按相邻帧随机拆分；
- 动态数据按完整 `episode` 拆分，不能把同一回合的时间步同时放进训练和测试；
- 真实温差序列按完整温差组或连续时间块拆分；
- 测试扰动和测试硬件条件在算法确定后封存；
- 保存 Git 提交、配置快照、数据哈希、随机种子和仿真器版本。

## 8. 当前静态模型输入

现有 `src/dataset_holo.py` 会把每帧转换为：

```text
input[0] = normalized_intensity
input[1] = wrapped_phase
```

形状：

```text
[2, height, width]
```

其中：

```text
normalized_intensity = intensity / max(intensity)
wrapped_phase = angle(exp(1j * phase))
```

这是现有 ResUNet 的静态输入格式，不等同于未来 RL 的时序观测契约。
