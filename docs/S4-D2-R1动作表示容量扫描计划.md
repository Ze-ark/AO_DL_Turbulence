# S4-D2-R1 动作表示容量扫描计划

## 结论先说

下一步先不训练强化学习，也不改算法。我们要回答一个更基础的问题：控制器原来只能沿着10个方向修正波前，会不会是“能修的形状太少”，所以无论怎样训练都过不了2%门槛？

本实验比较10、21、36和256个修正方向。这里的“256维”不是神经网络有256个隐藏单元，而是控制器可以组合256种不同的相位形状。只有正式扫描证明某种表示确实有足够上限，才值得据此设计下一版强化学习；即使通过，也不自动授权训练R2、打开S4-D3或操作真实SLM。

## 小白版原理

可以把波前补偿想成用一盒彩笔临摹图案：

- 10维：只有10种基础笔画；
- 21维和36维：增加更细的圆形波纹笔画；
- 256维：保留原来的10种笔画，再加入更多局部空间笔画。

笔画更多不代表一定更好。256维也可能更难控制、对配准误差更敏感。因此本实验只改变“可以画哪些形状”，不允许256维使用更大的总相位能量。

## 公平比较怎么保证

四种表示都保留完全相同的前10个Zernike（泽尼克）低阶模式，并共享同一传统控制器、扰动、硬件误差、测试回合、预见时域和评价门槛。

动作同时经过两层限制：

1. 每个方向的残差不超过±0.05 rad，最终单步不超过±0.15 rad；
2. 所有方向合起来的总相位均方根预算固定为旧10维动作的水平：残差约0.1581 rad，最终单步约0.4743 rad。

因此，256维只能更灵活地分配同一份“动作预算”，不能因为维数多就凭空获得更大能量。输出会分别记录“控制器原本想请求多少”和“经过公平限制后实际执行多少”，不能把两者混为一谈。

## 正式实验设计

| 项目 | 设置 |
|---|---|
| 动作表示 | 10、21、36维Zernike；256维混合空间基 |
| 硬件误差档位 | 标称、3帧延迟、50%稳定速度、中等配准、严重配准、组合中等 |
| 动态条件 | 冻结流、带沸腾定风、带沸腾变风和噪声 |
| 每个条件 | 16个完整回合，每回合200步 |
| 未来预见 | 0—6帧，逐回合选择乐观上限 |
| 规模 | 18个场景、522条进度任务、576行汇总记录 |
| 设备 | 必须使用CUDA；不可静默回退CPU |

本实验会使用精确仿真配准参数和未来真值，因此得到的是“理论上有没有容量”，不是现实中可部署的控制器性能。

## 通过门槛

候选表示需要同时满足：

- 相对冻结传统控制器的桶内功率增益至少2%；
- 桶内功率和Strehl（斯特列尔比）改善的95%置信区间下界大于0；
- 相位均方根误差改善的95%置信区间上界小于0；
- 违规率不超过5%；
- 中等配准与严重配准两个目标档位也要通过。

还会把21、36、256维与10维锚点做同回合配对比较。不能只看平均值较高就宣布成功。

## 已完成的运行前检查

- 四套基都保持正交，且前10个锚点没有被改变；
- 所有配准逆映射都保持满秩；
- 256维在严重配准下的条件数约79.8，说明它可能放大误差，正式实验会在动作预算约束下检验实际后果；
- 严格真值对齐容差固定为`1e-6`，没有因首次正式运行的数值错误而放宽；
- 首次正式运行完成522/522条任务后暴露float32消差问题，失败现场已保留；
- 修复后改为直接投影湍流真值，原故障场景和CUDA快速冒烟的对齐误差均为`0`；
- 修复后CUDA快速冒烟完成7/7条进度，8条场景记录和16项源码哈希均完整；
- 快速冒烟只有2个回合，只证明程序能运行，不能说明256维优于10维。

故障证据、归档位置和修复验证见[S4-D2-R1动作表示容量扫描失败诊断记录](S4-D2-R1动作表示容量扫描失败诊断记录.md)。

## 用户在IDE中运行

正式扫描不是训练，但按项目协作规则仍由用户在IDE集成终端启动：

```powershell
.\.venv\Scripts\python.exe scripts\run_s4_representation_capacity.py --config configs\experiments\s4_representation_capacity_v1.yaml
```

程序会显示当前任务数、总任务数、已用时间、预计剩余时间和CUDA显存，并持续写入：

- `outputs/s4_representation_capacity_v1/progress.jsonl`
- `outputs/s4_representation_capacity_v1/scenario_records.csv`
- `outputs/s4_representation_capacity_v1/summary.json`
- `outputs/s4_representation_capacity_v1/source_manifest.json`

完成后通知助手“`动作表示容量扫描完成`”。助手先做只读审计，再决定是设计新的动作表示、停止当前RL路线，还是在有充分证据时提出R2实验方案。

## 安全与结论边界

- 不训练模型，不更新优化器或检查点；
- 不读取旧轨迹，不接触S4-D3封存数据；
- 不发送真实SLM图案；
- 快速结果、目标值和正式结果必须分开；
- 正式结果即使通过，也只说明动作表示“有潜力”，不等于RL已经有效。
