# S4-D2-R5-2 信息隔离审计记录

## 结论

R5-2-v4 的策略输入信息隔离审计通过（`PASS_WITH_SCOPE`）。代码路径显示，策略只接收 `R4Interface.snapshot()` 产生的历史观测及其有效位；没有直接读取湍流真值、未来帧、Strehl、桶内功率真值或硬件档位标签。该结论只覆盖信息隔离，不代表策略已经优于冻结积分器，也不代表真实 SLM 闭环已经完成。

## 审计对象

- 训练输出：`outputs/s4_r5_policy_training_v4`
- 策略入口：`src/rl/r5_policy_training.py`
- 因果特征：`src/rl/r5_physics_adapter.py`
- 批量环境：`src/rl/r5_batched_environment.py`
- 观测接口：`src/rl/r4_observation.py`
- 合同测试：`tests/test_r5_causal_contract.py`、`tests/test_r5_physics_adapter.py`、`tests/test_r5_batched_slm.py`

## 逐项检查

| 检查项 | 证据 | 判定 |
|---|---|---|
| 策略输入来源 | `ResidualGRUPolicy.forward(history, valid)` 只调用 `causal_policy_features(history, valid)` | 通过 |
| 特征白名单 | 由历史中的残余模态、动作/执行器估计、修正量、已到达功率和时间戳组成；`validate_history` 先校验合同 | 通过 |
| 湍流真值隔离 | `R5BatchedEnvironment.proxy()` 仅取环境观测的前 21 维并加显式测量噪声；真值不进入策略接口 | 通过 |
| 未来帧隔离 | `R4Interface` 按“动作后下一观测”推进，历史只追加当前已到达观测 | 通过 |
| Strehl/桶内功率真值隔离 | `env.step()` 返回的 `info` 只被转换为已到达的功率测量，进入接口历史或目标计算；没有把 Strehl 或真值功率传入网络 | 通过 |
| 硬件档位隔离 | profile 只影响 SLM 动力学、量化、延迟、配准和测量噪声；没有 profile id 或参数拼接到策略特征 | 通过 |
| 请求动作与实际动作 | 接口保留请求动作、执行器估计和时间戳，策略不能读取未到达的未来结果 | 通过 |
| 训练边界 | `summary.json` 明确 `confirmation_access=false`、`real_slm_actions=false`、`s4d3_access=false`，且 `policy_leakage_verified` 在确认前保持 false | 通过 |

## 证据边界

本审计没有读取独立确认轨迹，也没有重新运行正式确认实验。因此尚不能回答：

1. R5 策略是否超过冻结积分器（增益 0.15、泄漏 0.10）；
2. 在全新随机种子和未见扰动上是否保持收益；
3. 是否满足 Strehl、桶内功率、相位 RMSE、违规率、延迟和失败率门槛；
4. 是否可以迁移到双 SLM 或真实大气。
