## 这次只回答一个问题

把独立训练湍流回合从96条增加到384条，能否让同一个模型更可靠地判断“这个修正动作到底有没有帮助”？

A6出现训练集好、未见回合差的现象。我们先检验数据不足，而不是直接认定算法错误、盲目扩大网络或重新启动完整强化学习。

## 对照设计

| 项目 | 小数据组 | 大数据组 |
|---|---:|---:|
| 独立训练回合 | 原有96条 | 同样96条＋新增288条 |
| 每个策略种子的训练动作对 | 1728 | 6912 |
| 原有验证回合 | 同一批48条 | 同一批48条 |
| 新的共同测试回合 | 同一批96条 | 同一批96条 |
| 每次拟合更新次数 | 10000批 | 10000批 |
| 每批样本数 | 256 | 256 |

每条回合包含一种固定湍流条件；相同种子在6个硬件仿真档位、3个探针时刻的重复测量仍属于同一回合簇。3个原策略种子、2种既有损失、2种数据规模，共12次监督拟合，不把三个策略的数据混起来训练一个模型。

输入仍为210维状态加11维动作，网络仍为两个256单元隐藏层、SiLU激活，学习率0.0003。标签仍为同一状态下演员动作相对零动作的16步实际折扣累计奖励差；不包含评论家对未来的估计。桶内功率差是独立物理核对指标，不能与训练奖励混为一谈。

归一化、类别权重、常数基线只由各自训练集计算，计算方法相同。两种规模与两种损失共享同一策略种子的初始权重与随机抽样种子；抽样范围随数据规模改变，这是预期差异。

为避免大组被早停截断，两组均关闭提前停止，跑满10000批，但仍只按验证集选择最佳检查点。相比旧A6，这改变了共同的停止方式，因此科学比较只在本次两组之间进行，不把A6旧分数直接当作小数据组结果。大组约有370次等效全数据遍历机会；这不是数学上的收敛保证。保留训练损失、最佳批次、末次检查点和样本覆盖率，若最佳点靠近预算末端，审计时明确标注预算可能不足，不能自动追加训练。

## 回合来源和隔离

- 复用A6的开发96条和验证48条，核对原始哈希，不读旧机制审计数据或A6旧测试数据来训练。
- 新训练条件与原开发条件完全相同。每种条件增加96条，按每批32条分三块采集；随机种子分别为3900032—3900127、3910032—3910127、3920032—3920127。
- 新测试使用原验证物理条件，每种32条，随机种子为3860000—3860031、3870000—3870031、3880000—3880031。它检验同一组预声明未见风速/风向条件的新回合，不代表所有大气条件。
- 新测试只在12个最佳检查点全部选定、哈希清单写入后生成；测试结果不得反馈到训练或检查点选择。
- 快速冒烟使用独立的偏移种子，不消耗上述新正式回合。所有阶段均禁用4000000起的S4-D3种子及真实硬件。
- 新原始动作对保留既有张量字段和32步曲线，训练只读取其中第16步的实际累计奖励；不会读取自举目标。每块及时保存，不覆盖旧数据。聚类依据全局回合种子，分块时纠正局部回合索引，避免把不同块错误并成同一回合。

## 预先固定的分析

主要比较是同一新测试回合上的“大数据组平衡准确率－小数据组平衡准确率”。按湍流条件分层、按完整回合配对重采样，保留同回合的全部硬件档位和时刻；不能逐行独立重采样。

报告点估计、普通95%区间和6个“策略种子×损失”比较的Bonferroni校正区间（总体错误率0.05，20000次重采样）。若同一种损失的三个策略种子均提高至少0.02，且校正区间下界均大于0，才标记“本次扩样有一致帮助”。0.02指平衡准确率增加2个百分点，不是光功率提高2%。如果区间跨0，结论是证据不足，不是证明扩样无效。固定96个测试回合是计算预算选择，没有据此宣称达到80%统计功效；小效果可能无法分辨。

另保留A6完整可学习性门槛：验证和新测试均需平衡准确率≥0.60、95%回合区间下界>0.50、马修斯相关系数≥0.20、平均绝对误差优于训练均值常数预测；所有新测试硬件/条件分组均须两类齐全且平衡准确率≥0.50。总体改善与完整门槛通过分别报告，不能混为一个结论。这些门槛区间是诊断性区间，不替代上述扩样差值的多重比较校正。

无论结果如何，程序均在汇总后停止；不自动授权或训练评论家、完整强化学习，不自动改超参数或重跑。

区间反映给定训练数据和已训练模型下的新测试回合不确定性，不覆盖重新抽取训练集的全部变异。每个策略种子仅有一组嵌套训练集；三个策略共享湍流种子，不能作为三批独立天气样本合并统计。

## 运行方法

使用仓库根目录下的本地`.venv`，依赖见`requirements.txt`，正式计算必须通过`src/runtime.py`选择CUDA。仅助手的小型确定性单元测试可用CPU。

助手检查入口：

```powershell
.\.venv\Scripts\python.exe scripts\train_s4_r3_h16_data_scaling.py --preflight-only
.\.venv\Scripts\python.exe scripts\train_s4_r3_h16_data_scaling.py --quick
```

正式任务由用户在IDE集成终端启动一次：

```powershell
.\.venv\Scripts\python.exe scripts\train_s4_r3_h16_data_scaling.py --config configs\experiments\s4_r3_h16_data_scaling_v1.yaml
```

程序依次执行“新增训练回合采集→12次拟合→冻结所有最佳模型→新测试回合采集→共同评估”。采集阶段可能比网络训练更耗时；终端分阶段显示进度、预计剩余时间和CUDA显存，训练阶段另显示当前批次、平均损失和验证成绩。每100批写入日志，采集每个批量分支写一次日志。现有输出目录会被拒绝，不支持自动重试、覆盖或续跑。

## 输出、监测与停止

输出目录：`outputs/s4_r3_h16_data_scaling_v1/`；快速冒烟使用单独目录。主要文件：

- `datasets/`：新增动作对、合并后的训练动作对和新测试动作对及各自哈希；
- `seed_*/small/`、`seed_*/large/`：两种损失各自的最佳和末次检查点、`progress.jsonl`、`loss_history.csv`；
- `TRAINING_FROZEN.json`：新测试生成前冻结的全部最佳检查点；
- `data_manifest.json`、`source_manifest.json`：数据/配置/源码追溯；
- `fit_summary.csv`、`scaling_comparison.csv`、`test_subgroups.csv`：单模型成绩、配对扩样比较和所有测试分组；
- `summary.json`：运行是否完整、假说证据及限制。它存在不代表科学门槛通过。

阶段日志90秒不增长时先检查进程和GPU，不自动判断卡死；采集分支耗时可能不均匀。正式运行由用户控制停止时间，不设置会自动杀死用户训练的超时。助手CUDA冒烟上限10分钟，若失败保留现场并报告，不自动重试。完成后用户通知“A7训练完成”，助手只读审计结果。
