# R4-1B2传统基座筛选准备

现在可以由用户启动正式筛选。它不是训练强化学习，而是让18组传统控制器做同一套题，选出后续新算法必须超过的参照。正式筛选尚未运行，尚无最强基座结论。

## 在IDE中运行

在项目根目录的集成终端运行一次：

```powershell
.\.venv\Scripts\python.exe scripts/select_s4_r4_baseline.py --config configs/experiments/s4_r4_baseline_selection_v1.yaml
```

程序显示候选编号、总进度、当前回合步数、预计剩余时间和CUDA显存，持续写入 `progress.jsonl`。本轮不更新模型，所以没有训练损失。运行完成后告诉助手“R4-1B2传统基座筛选完成”，再进行只读审计，不自动进入下一实验。

只检查准备条件可加 `--preflight-only`。不要重复运行已完成的 `--quick`；已有输出目录会触发保护，不会覆盖。报错时保留输出，不自动重试；程序不提供断点续跑。异常前完成的轨迹批次与日志保留，未完成批次不保证完整落盘。

## 本次比较什么

- 三类方法：泄漏积分器、跟踪补偿控制器、使用冻结线性预测器的控制器。
- 每类使用3个增益（0.15、0.25、0.35）和2个泄漏系数（0.05、0.10），共18组；跟踪系数0.5，线性预测2步。
- 每组共享96条开发天气、6个误差档位、每回合200步；按完整天气比较，不挑选好看的帧。
- 总计10,368个回合、2,073,600次物理仿真转移、4,147,200个线性模型前向样本。训练更新、模型预测控制（MPC）调用、独立确认数据访问和真实SLM动作均为0。
- 天气起始种子为3762048、3762304、3762560，各32条；与原训练天气分开。需要CUDA和至少4 GiB可用磁盘，禁止静默回退CPU。

选择规则在本轮结果产生前已经由[上一阶段记录](S4-D2-R4-1B2传统基线与安全冒烟记录.md)锁定：先检查有限数值与请求动作约束；相对原跟踪基座（配置索引9，增益0.25、泄漏0.10），平均实际违规率增加不能超过0.001，即0.1个百分点；在合格候选中选择平均桶内功率最高者，完全同分取配置顺序靠前者。天气类型、档位、天气等权平均。出现非有限值、越界请求或异常终止，整个程序停止，不丢弃坏回合后继续选优。

这只是开发集上的选择，不是独立显著性检验，也不代表所选控制器没有执行器限幅。像素饱和、像素变化率限制分别记录；合并违规指标取环境定义，不能把模态请求合法误写成像素限幅为零。
