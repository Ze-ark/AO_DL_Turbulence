# G2-D5：延迟功率梯度与硬前向诊断

## 先说结论

G2-D4 已证明，等预算训练后的两组冻结策略在相同输入下主要差在动作**幅度**，但“第一帧训练评分较高、第五帧物理功率较低”不能证明训练代码的跨帧梯度有错：原训练确实把完整 200 帧评分汇总后反向传播。本诊断不训练模型，只检查一次动作的梯度能否穿过仿真 SLM 延迟，以及量化代理梯度是否与实际硬前向的有限幅度变化方向一致。它不是完整闭环排名，更不能替代独立确认。

## 固定问题与判别

1. 在同一积分器来源状态下，冻结两组 G2-D2 第 512 次更新的策略，部署倍率均保持 1.75。将策略输出的 11 维修正作为独立求导变量，只发一次动作，后四帧保持请求不变。
2. 分别求第一至第五帧**无噪声仿真桶内功率**、五帧平均功率和第一帧动作及平滑惩罚对该修正的梯度。记录未连通、数值零、非有限、范数、径向方向和裁剪比例。延迟生效前的零梯度是预期物理现象；生效后仍没有梯度时，才沿动作投影、量化、限速和功率链路排查。
3. 从完全相同的来源状态及随机流，用动作倍率 `0.95` 和 `1.05` 重新运行硬前向。这不是数学上的无穷小导数：量化是阶梯函数，训练却使用直通代理梯度。因此只比较有限变化的方向、大小和裁剪状态，不要求两者逐点数值相等。
4. 将梯度和硬前向结果按硬件条件、天气、湍流类型、档位、初始化和探针时刻保留；独立天气是统计单位，重复探针不能冒充独立样本。

## 数据与边界

- 新开发天气从 `7,320,000` 起，短冒烟与正式诊断采用不同种子；不得触碰预留的 `7,200,000` 独立确认集。
- 标称同槽和新六档硬件条件同时检查；两组策略与积分器来源状态、动作约束及外生随机流保持配对。程序应拒绝覆盖已有输出，记录配置、检查点和运行环境哈希。
- 只使用 CUDA 仿真，不调用真实两台 `FSLM-2K73-P04`，不读取真实 SLM 校正文件，不产生训练更新。
- 本诊断若显示代理梯度与硬前向常反号，只能指出局部物理代理的风险；若二者同向，也不能证明完整 200 帧训练目标、泛化或独立性能达标。下一层才比较完整闭环训练天气与新开发天气、并检查目标分量。

## 停止与解释规则

程序、配对状态、随机流、梯度有限性、文件哈希或预算不完整时先停止审计，不基于残缺输出调算法。正式结果只作开发机制解释，不改变 G2-D3 的失败判定、不放宽 1.05% 开发门槛或独立确认门槛，不凭它挑选下一次确认模型。
