这一步仍然不训练。它要验证评论家是否像一个“打分失准的教练”：明明给某个动作高分，
这个动作实际执行后的未来总回报却更差。同时把训练奖励拆成三部分，确认微小功率改善
是否被动作惩罚或违规惩罚抵消。

## 怎样做到公平比较

每个探针都从完全相同的仿真状态开始，只改变第一步候选动作：

| 候选动作 | 含义 |
|---|---|
| `reverse_actor` | 演员动作反向 |
| `zero` | 第一步不加RL修正 |
| `quarter_actor` | 第一步使用25%演员动作 |
| `actor` | 第一步使用完整演员动作 |
| `ideal_teacher` | 第一步使用仿真理想教师，仅作诊断 |

第一步之后，五个分支都继续使用同一个冻结确定性演员32步。这样比较的是“在同一个
状态下，第一步选哪个动作更好”，不会把不同后续控制器混进结论。

共同前缀只使用冻结学生策略。每个回合在第`0、80、160`帧设置探针，覆盖初始、中期
和后期状态。

## 检查哪些量

评论家校准面板记录：

- 两个评论家各自的Q值、较小Q值和双评论家分歧；
- Q值的候选动作排序；
- 32步折扣回报的候选动作排序；
- 成对排序正确率、最高分动作一致率；
- “评论家说演员优于零动作，但真实回报更差”的比例。

奖励分解严格满足：

```text
训练回报 = 测量功率贡献 - 动作惩罚 - 违规惩罚
```

程序分别累计四项并检查数值闭合误差。真实无噪桶内功率另行保存，不与带噪训练奖励
混为一谈。

## 解释边界

SAC的理论软Q还包含随机策略和熵项。本诊断使用正式部署时的确定性演员，因此回答的
是“评论家能否正确排序部署候选动作”，不是精确复算SAC软贝尔曼目标。即使结果确认
部署排序失败，也不能直接声称某一行SAC公式或代码必然错误。

预声明机械结论包括：

- 三个主要种子都出现“Q认为演员更好、实际回报更差”，且整体排序差：确认部署排序
  失败；
- 三个主要种子的25%动作都提高真实功率回报但降低训练回报：确认奖励惩罚压制；
- 种子间不一致：保持混合或未确认，不挑最好种子；
- 奖励分解不能在`5×10⁻⁶`内闭合：诊断无效并停止。

所有结论均不自动授权重新训练、修改奖励、改算法或放宽门槛。
