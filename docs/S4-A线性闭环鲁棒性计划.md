## 先说结论

S3-B已经说明：目前的256维门控循环单元（GRU）没有比线性岭回归预测得更准。因此现在**不进入强化学习**，先回答一个更实际的问题：

> 简单、稳定的控制器接入两帧延迟的闭环后，能不能真的提高聚焦效果？

这一步叫S4-A。它仍是纯仿真，不会控制实验室的空间光调制器（SLM），也不会打开封存测试。

## 用小白语言理解这次比较

把湍流想成不断晃动的毛玻璃，控制器要提前让SLM做出相反的形状。

| 控制器 | 小白解释 |
|---|---|
| 不校正 | 什么也不做，用来当最低参照 |
| 直接投影 | 看见当前歪了多少，就立刻反向补多少 |
| 泄漏积分器 | 每次只补一部分，并慢慢忘掉很久以前的命令 |
| 两帧线性外推 | 根据最近两次变化速度，猜两帧以后会歪到哪里 |
| 多帧岭回归 | 根据过去8帧，用S3-B训练数据学一个稳定的线性预测公式 |

这里没有ResUNet，也没有强化学习。S3-B已经把“复杂神经网络是否值得继续”这扇门关上了，S4-A先把最强的线性闭环做好。

## 为什么要比较闭环，而不只比较预测误差

预测误差小，不一定等于光斑变好。控制器还会受到两帧延迟、相位范围、量化、单步变化限制和动作饱和影响。

所以本轮真正看的指标是：

- **桶内功率**：光斑中心小圆桶里收到了多少能量，越大越好；
- **斯特列尔比（Strehl）**：实际峰值和理想峰值的比例，越大越好；
- **残余相位均方根误差**：校正后波前还歪多少，越小越好；
- **违规率**：请求动作有多少超出仿真SLM的限制，越小越好；
- **动作代价和计算延迟**：不能只追求光斑而忽略执行负担。

控制器看到的是加入可控噪声的理想低维模态；科学指标始终由无噪声仿真真值计算。这样能检查控制器的抗噪性，但还不能代表真实全息相机。

## 数据怎么隔离

S4-A分成三套互不重叠的完整回合：

1. **调参条件**：只选择泄漏积分器和两帧外推器的参数；
2. **开发条件**：比较五种控制器并计算S4-A开发门槛；
3. **封存条件**：只在配置中登记，本脚本不生成也不评估。

岭回归只读取S3-B HDF5中的 `train` 组，不读取S3-B的 `validation` 组来拟合控制器。程序会检查所有回合种子互不重叠，并核对S3-B数据哈希。

## 通过条件

先在开发条件中选择桶内功率最高、违规率不超过5%的可部署控制器。它相对“不校正”必须同时满足：

1. 桶内功率配对差值的95%区间下界大于0；
2. Strehl配对差值的95%区间下界大于0；
3. 残余相位误差差值的95%区间上界小于0；
4. 总违规率不超过5%；
5. 每一个开发条件的桶内功率都提高；
6. 每一个开发条件都满足违规率限制。

这只是开发门槛。因为控制器选择和门槛计算使用了同一开发组，即使通过也不能直接形成最终论文结论；通过审计后才讨论是否打开独立封存条件。

岭回归还会单独与“最强非学习线性控制器”做配对比较。如果岭回归没有额外收益，就保留更简单的传统控制器，不为使用学习模型而使用学习模型。

## 运行方式

代码、配置和CUDA链路预检：

```powershell
.\.venv\Scripts\python.exe scripts\run_s4_linear_robustness.py --preflight-only
```

20帧快速冒烟已经由助手运行过，只证明程序链路可以执行，不用于研究结论：

```powershell
.\.venv\Scripts\python.exe scripts\run_s4_linear_robustness.py --quick
```

正式开发比较由用户在IDE集成终端运行：

```powershell
.\.venv\Scripts\python.exe scripts\run_s4_linear_robustness.py
```

终端会分别显示调参和五种控制器比较的实时进度、预计剩余时间及CUDA显存。正式运行会拒绝覆盖已有结果。
