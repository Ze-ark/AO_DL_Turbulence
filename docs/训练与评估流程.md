# 训练与评估流程

本文档区分静态原型、已验证的 S1—S2 动态纯仿真、已经就绪的 S3 动力学前置门槛，以及尚待实现的强化学习和真实闭环。不要把其中任何纯仿真输出当作真实硬件结果。

## 0. 训练协作方式

从 S3 开始，正式训练由用户自己在 IDE 的**集成终端**启动，助手不代跑。助手的职责是：

1. 训练前准备脚本、配置、测试和准确命令；
2. 训练脚本实时显示总轮次、当前批次、平均损失、预计剩余时间和 CUDA 显存；
3. 每轮结束立即刷新损失 CSV，最佳模型单独保存；
4. 用户训练完成后通知助手，助手再读取日志、权重摘要和最终 JSON；
5. 训练崩溃时不自动重试，先保留报错并分析原因。

建议使用 PyCharm、VS Code 等 IDE 内的终端运行，而不是不支持动态刷新的简化输出窗口。进度显示大致如下：

```text
模型训练总进度  4/20
训练 4/20       31/100批  平均损失=0.08321  显存=3.20/4.10GB  剩余时间=...
```

训练完成后，只需告诉助手“训练完成”，并保留终端最后几十行输出。助手会从配置中定位对应的 `loss_history.csv`、最佳检查点和 `summary.json`，不需要手工复制所有数值。

## 1. 准备 Python 环境

项目强制使用 CUDA GPU，不允许静默回退到 CPU。

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

检查 CUDA：

```powershell
.\.venv\Scripts\python.exe -c "import torch; print(torch.__version__); print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0))"
```

必须看到：

```text
torch.cuda.is_available() = True
```

CUDA 不可用时停止，不切换到 CPU 继续正式训练。

## 3. 新动态闭环仿真流程

S1 动态环境和 S2 最终纯仿真比较已经实现并验证；强化学习训练入口尚未实现。继续严格按以下阶段推进。

### S0：物理 Gate 0

状态：`已通过物理单元测试，15/15；后续 S1 动态核心也已实现`。

必须通过：

- 空间相位屏与频域传播交替正确；
- 所有相位屏都被使用；
- 零湍流接收面结果与理论参考一致；
- `r0` 使用完整传播路径定义；
- 动作会改变接收面或焦平面评价；
- 训练、验证和测试场景完全分开。

### S1：动态环境

状态：`核心环境已验证；MATLAB S1 3/3，跨语言误差 6.66×10⁻¹⁶；Python 测试数以最近一次完整测试为准`。

建立：

```text
观测(t) → 动作(t) → 系统演化 → 观测(t+1) + 奖励(t)
```

首轮使用低维可控模态，不直接让 RL 输出 2048 × 2048 像素动作。

GPU 冒烟运行：

```powershell
.\.venv\Scripts\python.exe scripts\run_s1_smoke.py --steps 50
```

MATLAB 与 PyTorch 冻结流数值对照：

```matlab
export_s1_cross_language_reference( ...
    fullfile(pwd, 'data', 'processed', 's1_matlab_reference.h5'))
```

```powershell
.\.venv\Scripts\python.exe scripts\verify_s1_matlab_parity.py
```

S1 的 22 维观测是低维仿真真值，用于先判断控制器本身是否有效。S2 另外增加了统一的二维理想瞳面观测，供 ResUNet 使用；它仍不是真实全息观测。

### S2：传统控制基线

状态：`最终纯仿真门槛已通过并确定性复现；不代表 ResUNet 或 RL 获胜`。

至少完成：

1. 条件成立时的直接相位补偿或受约束投影；
2. 调优后的泄漏积分器；
3. 线性预测、LQG 或 MPC；
4. 统一观测下的 ResUNet 基线；
5. 可达到的模态子空间上限。

传统基线不稳定或不可重复时，不进入 RL。

当前可运行入口：

```powershell
.\.venv\Scripts\python.exe scripts\check_s2_resunet_transfer.py
.\.venv\Scripts\python.exe scripts\train_s2_dynamic_resunet.py
.\.venv\Scripts\python.exe scripts\run_s2_baselines.py --final
```

五项均已完成。旧静态 ResUNet 权重直接迁移失败，因此使用互不重叠的完整回合，在统一理想瞳面观测上从头训练动态无记忆 ResUNet。新模型通过感知测试，但最终闭环桶内功率低于泄漏积分器；这是有效的负结果。完整数值、统计和复现步骤见 `docs/S2传统基线验证记录.md`。

### S3：RL 先导实验

状态：`原GRU验证门槛FAIL；数据量/模型容量诊断等待用户在IDE训练；封存测试和RL尚未开始`。

- 先训练使用多帧历史的非线性动力学模型，并在未见条件上与 S2 线性预测器比较；
- 非线性动力学模型稳定优于线性模型时，比较同模型 MPC 与 PO4AO 式策略；
- 残差 SAC 作为第二候选；
- PPO 只作纯仿真补充；
- 同时运行时间打乱、删除动作历史和单步控制对照。

若 RL 不超过最强可部署基线，或删除历史后性能不变，就停止把它作为动态主控制器。

当前只运行第一步：

```powershell
.\.venv\Scripts\python.exe scripts\train_s3_dynamics.py --config configs\experiments\s3_dynamics_v1.yaml
```

该训练默认实时显示轮次、批次、误差、预计剩余时间和显存。它只校验封存条件元数据不重叠，不会生成或评估封存回合。完成后停止并通知助手读取 `outputs/s3_dynamics_v1/training/summary.json`，不要自行运行封存评估。完整门槛见 [S3 非线性动力学门槛计划](S3非线性动力学门槛计划.md)。

当前原实验已经运行并失败。下一步只做开发性数据量诊断：

```powershell
.\.venv\Scripts\python.exe scripts\train_s3_data_scaling_diagnostic.py --config configs\experiments\s3_data_scaling_diagnostic_v1.yaml
```

该入口固定每个模型 3600 次参数更新，比较 48、96、192、384 个完整回合，并在 192 回合下比较隐藏维度 32、64、128。总计 18 个模型，使用新训练/验证种子，不打开原封存测试。完成后通知助手“诊断训练完成”。详见 [S3 数据量诊断计划](S3数据量诊断计划.md)。

### S4：硬件化仿真

逐项加入：

- 相机噪声和曝光；
- 0—3 帧延迟；
- SLM 量化、相位范围和单步变化限制；
- 灰度—相位 LUT 偏差；
- 液晶稳定时间和迟滞；
- 坐标旋转、缩放、平移和漂移；
- 光功率计或焦平面评价噪声。

未知硬件参数先做保守范围随机化，H1 实测后替换为真实分布。

### S5：仿真到真实迁移

顺序固定为：

```text
冻结策略 → 真实数据影子运行 → 动作安全检查
→ 小幅双 SLM 硬件在环 → 经典控制器回退
→ 独立物理扰动
```

首轮真实系统不允许 RL 自由在线探索。

## 4. 正式评价规则

- 主要指标与训练奖励分开；
- 所有控制器使用相同测试轨迹、观测、动作约束和数据预算；
- 完整回合是拆分单位，不能随机拆散相邻帧；
- 至少报告平均值、置信区间、最差十分位、失败和回退次数；
- 同时报告性能、真实交互量、推理延迟和计算成本；
- 测试扰动在算法和超参数冻结后才打开。
