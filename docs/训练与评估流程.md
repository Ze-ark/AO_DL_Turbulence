# 训练与评估流程

本文档区分静态原型、已验证的S1—S2动态纯仿真、已经得到负结果的S3动力学门槛、S4传统控制器开发与未见验证，以及S4-D2残差SAC和未来真实闭环。动作表示容量扫描证明21维和36维存在理想容量，但R2正式SAC训练仍为FAIL；当前进入只读动作缩放与安全投影诊断，S4-D3保持关闭。不要把任何纯仿真输出当作真实硬件结果。

## 0. 训练协作方式

从 S3 开始，正式训练由用户自己在 IDE 的**集成终端**启动，助手不代跑。助手的职责是：

1. 训练前准备脚本、配置、测试和准确命令；
2. 训练脚本实时显示总轮次、当前批次、平均损失、预计剩余时间和 CUDA 显存；
3. 每轮结束立即刷新损失 CSV，最佳模型单独保存；
4. 用户训练完成后通知助手，助手再读取日志、权重摘要和最终 JSON；
5. 训练崩溃时不自动重试，先保留报错并分析原因。

建议使用 PyCharm、VS Code 等 IDE 内的终端运行，而不是不支持动态刷新的简化输出窗口。进度显示大致如下：

```text
模型训练总进度  4/20
训练 4/20       31/100批  平均损失=0.08321  显存=3.20/4.10GB  剩余时间=...
```

训练完成后，只需告诉助手“训练完成”，并保留终端最后几十行输出。助手会从配置中定位对应的 `loss_history.csv`、最佳检查点和 `summary.json`，不需要手工复制所有数值。

### S5：仿真到真实迁移

顺序固定为：

```text
冻结策略 → 真实数据影子运行 → 动作安全检查

```

首轮真实系统不允许 RL 自由在线探索。

## 4. 正式评价规则

- 主要指标与训练奖励分开；
- 所有控制器使用相同测试轨迹、观测、动作约束和数据预算；
- 完整回合是拆分单位，不能随机拆散相邻帧；
- 至少报告平均值、置信区间、最差十分位、失败和回退次数；
- 同时报告性能、真实交互量、推理延迟和计算成本；
- 测试扰动在算法和超参数冻结后才打开。
