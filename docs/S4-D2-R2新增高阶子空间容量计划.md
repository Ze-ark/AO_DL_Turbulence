# S4-D2-R2 新增高阶子空间容量计划

## 先说结论

模态分解已经证明：现有SAC策略的大部分损失来自第11维以后的高阶动作。但这只说明“模型输出了错误的高阶动作”，还不能说明“高阶方向本身没有用”。

下一步先做一个不训练的理想容量实验：前10维继续完全交给冻结传统控制器，仿真真值只在新增高阶维提出残差请求。如果这种“知道正确答案”的控制器都不能稳定提高2%，就不值得训练只控制高阶维的新RL模型。

## 小白版原理

可以把控制器想成两个人共同调旋钮：

- 传统控制器负责前10个“大旋钮”；
- 未来的RL只允许碰后面的“小旋钮”。

上一步发现，旧RL乱调小旋钮后系统明显变差。现在我们先让一个能看到仿真正确答案的“理想助手”只调小旋钮：

- 21维方案：传统控制器管前10维，理想助手只管新增11维；
- 36维方案：传统控制器管前10维，理想助手只管新增26维。

如果理想助手能够稳定改善，说明这些高阶旋钮有价值，只是旧RL没有学会；如果理想助手也失败，说明应停止这条高阶RL路线，而不是继续堆训练量。

## 与以前容量扫描的区别

以前的21维和36维容量扫描允许理想控制器同时调整全部维度，因此超过传统基线的收益可能来自重新调整前10维，也可能来自新增维。本实验把前10个RL残差请求强制为0，只检查新增维的独立价值。

程序仍保留统一的总动作能量、单维范围、最终单步范围和累计请求范围。安全投影可能轻微改变最后实际动作，因此会同时记录“请求动作”和“实际动作”，不能混为一谈。

## 正式设计

| 项目 | 设置 |
|---|---|
| 动作表示 | 21维Zernike中的新增11维；36维Zernike中的新增26维 |
| 传统控制器 | 冻结10维跟踪泄漏积分器 |
| 理想信息 | 仿真未来真值、精确配准参数 |
| 未来预见 | 0—6帧，逐回合选择最乐观结果 |
| 硬件误差 | 标称、3帧延迟、50%稳定速度、中等配准、严重配准、组合中等 |
| 动态条件 | 冻结流、带沸腾定风、带沸腾变风与噪声 |
| 每个场景 | 16个完整回合，每回合200步 |
| 正式计算 | 288组CUDA滚动任务 |
| 正式记录 | 288行场景、4608行逐回合记录 |
| 训练 | 0次，优化器更新0次 |

本实验使用320万命名空间的新开发种子，不读取或拼接以前的轨迹，也不访问S4-D3。

## 通过门槛

21维和36维分别判断。一个表示必须同时满足：

1. 总体桶内功率相对冻结传统基线至少提高2%；
2. 桶内功率和Strehl比改善的95%置信区间下界大于0；
3. 残差相位均方根误差变化的95%置信区间上界小于0；
4. 违规率不超过5%；
5. 六个硬件误差档位全部通过；
6. 中等和严重配准档位明确通过。

只有正式结果及独立审计通过，才允许设计下一版“RL只输出新增高阶维”的训练。PASS不等于RL已经成功。

## 用户在IDE运行

请在仓库根目录的IDE集成终端运行：

```powershell
.\.venv\Scripts\python.exe scripts\run_s4_high_order_capacity.py --config configs\experiments\s4_high_order_capacity_v1.yaml
```

运行时会显示总任务、当前动作维数、预见帧、功率差、预计剩余时间和CUDA显存。正式输出目录一旦创建就不会自动覆盖；若中途报错，请保留目录和原始报错，不要自行删除重跑。

## 输出文件

正式目录：`outputs/s4_high_order_capacity_v1`。

- `summary.json`：总体结果、各硬件档位结果和门槛；
- `scenario_records.csv`：每个预见时域及逐回合乐观包络的场景汇总；
- `episode_records.csv`：每个完整回合的候选、基线、差值和动作投影记录；
- `progress.jsonl`：实时进度；
- `preflight.json`：运行前证据与安全检查；
- `effective_config.json`：实际参数；
- `source_manifest.json`：运行时源码哈希。

## 正式结果后的决定

| 结果 | 下一步 |
|---|---|
| 21维新增11维PASS | 优先设计11维输出的高阶专用RL；36维仅作候选 |
| 21维FAIL、36维新增26维PASS | 谨慎设计26维高阶RL，并先处理更强投影和配准敏感性 |
| 两者都PASS | 仍优先选择维数更小、约束更轻的21维方案 |
| 两者都FAIL | 停止新增高阶残差RL路线，不再增加SAC训练量 |
| 真值或前10维请求完整性失败 | 不解释科学结果，先修程序 |

运行完成后告诉助手：`新增高阶子空间容量运行完成`。助手会先只读审计，再决定是否允许准备下一轮RL训练。

在审计完成前，不训练新模型、不更换算法、不打开S4-D3、不操作真实SLM。
