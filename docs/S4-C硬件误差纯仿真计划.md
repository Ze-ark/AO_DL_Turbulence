## 小白版目标

S4-B已经说明泄漏积分器在比较干净的动态仿真里有效。S4-C接下来只问一个更接近实验室的问题：

> 如果SLM反应变慢、相位不准、画面有偏移、观测有噪声，它还能不能把光斑变得更集中？

本阶段不训练新模型、不使用强化学习，也不连接真实SLM。

## 为什么分成C0和C1

| 子阶段 | 参数从哪里来 | 能说明什么 |
|---|---|---|
| S4-C0 | 保守假设范围 | 找出系统最怕哪种硬件误差，指导之后标定 |
| S4-C1 | H1对两台SLM的实测结果 | 判断冻结控制器在实验室设备分布下是否仍值得进入影子测试 |

C0的数值是假设，不得写成中科微星设备的真实性能。H1完成后必须保留C0结果，并新建C1配置，不能覆盖C0。

## 冻结内容

S4-C不重新挑控制器，继续使用：

```text
leaky_integrator(gain=0.35, leak=0.10)
```

比较对象仍是不校正。两者必须使用相同扰动、相同观测噪声和相同硬件误差随机数。

## C0逐步加难度

先单独加入一种误差，确认是哪一种导致性能下降；最后才把多种误差叠加。

| 组别 | 加入的误差 | 第一版保守范围 |
|---|---|---|
| C0-基准 | 仅保留已有SLM模型 | 2帧延迟、256级量化、单帧最大变化0.35 rad |
| C0-延迟 | 显示和计算等待 | 1、2、3帧 |
| C0-量化 | 相位只能取有限等级 | 64、128、256级 |
| C0-LUT | 请求相位与实际相位比例不准 | 0.85、1.00、1.15倍 |
| C0-稳定时间 | 液晶不能一步到位 | 每帧完成目标变化的50%、75%、100% |
| C0-配准 | SLM图案发生平移和旋转 | 平移0、1、2像素；旋转0°、0.5°、1° |
| C0-观测噪声 | 重建相位不完全准确 | 0.02、0.05、0.10 rad |
| C0-功率噪声 | 功率计读数波动 | 相对标准差0%、1%、3% |
| C0-组合中等 | 多项常见误差同时出现 | 各项中间档 |
| C0-组合严重 | 多项保守误差同时出现 | 各项最严重档 |

这些范围只用于压力测试。实现时必须把每个误差开关和数值写入YAML，不能散落在代码里。

## 数据和拆分

- 使用全新的开发种子，不复用S4-A或S4-B种子；
- 共3种物理条件；每个硬件档位在每种物理条件下运行32个完整回合，每回合200帧，即每个硬件档位96个回合；
- 同一回合中，不校正与泄漏积分器共享同一湍流和硬件误差；
- S4-B输出目录只读，不从中选择C0参数；
- C0允许诊断和修改仿真代码，但参数冻结后才生成C0最终结果；
- C1另设未见种子，并在H1参数冻结后只运行一次。

## 主要评价指标

主要指标仍是桶内功率，因为它直接描述焦点附近收集到了多少能量。Strehl比和残余相位误差用于交叉检查，防止只优化一个数值。

每个条件都报告：

1. 桶内功率；
2. Strehl比；
3. 残余相位均方根误差；
4. 请求动作和实际动作差异；
5. 饱和、变化速度受限和其他违规率；
6. 动作计算时间和总闭环延迟；
7. 失败或回退次数。

训练奖励不能代替这些独立指标。

## C0通过门槛

冻结泄漏积分器必须同时满足：

以下门槛对每个必过硬件档位分别计算；一个档位内部只合并它自己的3种物理条件，不能把不同硬件档位重复使用的物理种子当成更多独立样本：

1. 桶内功率配对差值95%区间下界大于0.05；
2. 平均桶内功率相对增益至少10%；
3. Strehl差值95%区间下界大于0；
4. 残余相位误差差值95%区间上界小于0；
5. 总违规率不超过5%；
6. 每个单误差条件的桶内功率都提高；
7. 组合中等条件必须通过；
8. 组合严重条件允许作为失效边界，但必须明确记录，不能删除后只报告成功条件。

C0通过只允许进入“等待H1实测并制作C1配置”，不授权RL或真实SLM动作。

## 已实现的程序结构

```text
configs/experiments/s4_hardware_stress_v1.yaml
src/simulation/hardware_effects.py
scripts/run_s4_hardware_stress.py
tests/test_s4_hardware_effects.py
outputs/s4_hardware_stress_v1/
```

只读预检入口为：

```powershell
.\.venv\Scripts\python.exe scripts\run_s4_hardware_stress.py --preflight-only
```

不落盘的CUDA快速冒烟入口为：

```powershell
.\.venv\Scripts\python.exe scripts\run_s4_hardware_stress.py --quick
```

正式入口为：

```powershell
.\.venv\Scripts\python.exe scripts\run_s4_hardware_stress.py
```

正式运行仍由用户在IDE集成终端启动，CUDA不可用时立即停止。它固定比较“不校正”和冻结泄漏积分器，覆盖17个硬件档位、3种物理条件，共执行20400个CUDA批处理时间步。16个档位参与总门槛，组合严重档只用于记录失效边界。输出目录已经存在时程序拒绝覆盖。

预检和快速冒烟均不写入正式输出。快速冒烟的回合数很少，只能证明软件链可运行，不能用于算法排名或论文结论。

## 必须补齐的记录

S4-C相对S4-B新增三项追溯要求：

1. 源码清单必须包含 `src/simulation/slm.py` 和新的硬件误差模块；
2. HDF5逐步保存动作计算时间、请求动作、延迟队列输出和实际动作；
3. 运行结束后生成轨迹文件SHA-256清单，后续审计先验哈希再读数据。

## 停止条件

出现以下任一情况就停止，不转向RL：

- 桶内功率提高，但Strehl和残余相位同时变差；
- 性能只来自超过限制的动作；
- 组合中等条件下已经不如不校正；
- 结果依赖读取仿真中的真实扰动相位，而不是声明的观测；
- CUDA、种子、配置或文件哈希无法追溯。
