# G2-D7 完整回合硬前向诊断审计记录

## 结论

在冻结策略、完整 200 帧的**纯仿真硬前向闭环**中，把部署倍率从 `1.6625` 提至 `1.8375`，24/24 个配对组的无噪声桶内功率均上升，原训练评分却均下降；上升的动作惩罚超过测量功率增益。硬前向的评分方向与 G2-D6 可微代理梯度 24/24 一致，**没有发现“梯度方向普遍写反”**。结合 [G2-D6](S4-D2-R5-G2-D6完整回合目标分解审计记录.md)，目前最具体的解释是：现行目标中的动作幅度惩罚，在这些冻结策略附近偏好较弱但光学效果较差的动作。

这定位的是**局部评分机制**，不是“已证明该惩罚造成训练失败”，更不是新算法过门槛。G2-D3 原 `1.05%` 开发继续条件、G1 新硬件档位臂 FAIL、独立确认和真实 SLM 状态均不变。

## 解释边界与下一步

依据 `academic-research-suite` 的 11 类统计与方法谬误清单逐项检查（11/11）：最关键的是**伪重复**与**训练因果外推**。只有两个独立开发天气，不做显著性检验或性能置信区间；24 个配对比较来自天气、初始化及两训练臂的重复结构，不是 24 个独立天气。D7 是对已训练权重的部署倍率干预，直接分解了当前评分为何压低有用的力度，却未单因素改变训练时的动作惩罚；优化路径、初始化和其他目标项仍可能共同作用。只可称“在当前纯仿真冻结策略附近，动作惩罚直接造成评分与光学功率反向”，不可称“动作惩罚已被证明是失败的唯一原因”。

下一步是**一次预注册、等预算的动作惩罚单因素训练消融**：固定训练/部署倍率、暖启动、天气、优化预算、平滑项、观测和安全投影，只比较原权重 `0.01` 与去除该项的 `0`；先用全新开发天气与冻结积分器公平配对，过原开发继续门槛才另行设计独立确认。`0` 是机制检验，不是根据 D6 事后交叉点调出来的最优值。正式模型训练仍由用户在 IDE 手动启动；助手可以准备代码、配置、测试和进度显示，但不自行启动训练。

Material Passport：`academic-research-suite / experiment-agent`；模式 `validate`；验证状态 `ANALYZED`（限于两组开发天气的仿真机制，不是独立性能结论）。
