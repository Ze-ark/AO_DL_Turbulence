# R4-1B1-D1：查清历史和后续指令的影响

结论：本轮不训练、不采集新湍流，只用B1已经保存的数据和三份冻结模型，定位下一次修改应优先解决什么。原B1失败结论不变。

## 用户运行入口

在项目根目录的IDE终端执行一次：

```powershell
.\.venv\Scripts\python.exe scripts/diagnose_s4_r4_response_attribution.py --config configs/experiments/s4_r4_response_attribution_v1.yaml
```

正式结果保存在 `outputs/s4_r4_response_attribution_v1/`；实时显示完成批次、总批次、预计剩余时间和CUDA显存。结束后通知“R4-1B1-D1诊断完成”。不自动重试；出现异常或输出目录已存在时，保留原文件再审计。

## 三组对照

三组共用同一物理状态、同一动作配对、同一8步目标、同一噪声阈值和同一三模型集合，不再比较不同天气来推测历史作用。

| 组别 | 模型看到什么 | 用途 |
|---|---|---|
| 原模型重放 `full_self` | 全部已有历史，后续指令由自己的预测生成 | 必须与B1保存的三个模型输出和指令逐项精确一致，否则停止 |
| 遮蔽旧历史 `current_self` | 初始只给当前帧，后续预测帧正常积累 | 检查相同状态下旧历史信息的作用 |
| 已知后续指令 `full_recorded_commands_privileged` | 全历史，并额外提供物理分支已经记录的后续请求指令 | 隔离后续指令续推误差；仅是使用额外信息的诊断，不可部署 |

历史遮蔽只影响模型输入；控制器自己的名义指令队列和当前执行状态估计继续保留，避免把“少看历史”混成“执行器延迟模型被改了”。不填造第0步之前的历史，不补入真实相位。第0步本来就只有1帧，因此前两组应精确相同，作为负对照。

第三组仅接收记录的请求增量，不读取实际加载相位、无噪功率或未来观测。它使用了真实部署时不可提前知道的后续指令，任何改善都不能冒充可部署控制收益，也不保证构成理想上限。

## 预算与冻结边界

- 复用B1的96条开发天气、6个硬件误差档位、3个时刻和11个高阶模态；共38,016对动作、108组起始状态批次。
- 三组、三个模型的8步重放合计2,861,568个单样本单步预测；新增物理转移0，模型更新0，RL更新0。
- 不接触独立确认数据、不做MPC、不操作SLM；没有新的正式泛化证据。
- 保持原来的训练端噪声阈值；全部配对输出，不丢弃难例。综合硬件误差档位可能仍无可辨识方向，应报告为信号不足而非0分。

## 分析方法与解释限制

主要配对比较限定在初始已有8帧历史的相同状态（原第80、160步）：①全历史准确率减遮蔽历史准确率；②已知后续指令准确率减自行续推准确率。两项比较使用相同天气抽样，按天气整体、在天气类型内分层重采样20,000次；每项给97.5%区间，对两项比较做邦费罗尼区间调整。它们是B1负结果后的开发性机制诊断，不是预先独立确认，区间不能消除开发集复用带来的限制。

同时报告各组全体/各时刻/各天气类型/各硬件档位的平衡准确率、可辨识数量、全部配对的功率变化预测均方根误差及实际变化量均方根。准确率只用原阈值以上的配对；误差计算不筛低信号配对。辅助分组仅作描述，不事后挑最佳子集。

即使全历史明显优于遮蔽历史，也只能说明模型依赖历史，不能精确归因“原第0步失败有多少百分比由缺历史造成”；遮蔽也可能带来分布变化。即使已知指令组改善，也只是指令条件化敏感性的证据；不改善不等于证明代码完全正确。

本轮不设新的“通过即训练”门槛，不给原因分摊百分比。结束后停下只读验收，结合误差和对照决定是否需要修改目标、数据覆盖或观测；不自动扩样、改模型或放宽原60%门槛。

## 输出与小型验证

- `predictions/*.pt`：每个起始批次的三组、三模型、各分支逐步功率预测，及相对记录指令的均方根差；维度顺序为组别、模型、天气、时间。`valid_initial` 保留初始历史长度，输入源路径可追溯。
- `pairs.jsonl`：保留原天气、档位、时刻、模态、方向、实际变化量和阈值，新增 `initial_valid`、`predictions`（三组集合均值）、`member_predictions`（三组×三模型变化量）。
- `summary.json`：配对区间、分组误差、精确重放检查、预算与停止边界。主状态只表示诊断完成，不写B1通过。
- `preflight.json`、`effective_config.json`、`runtime.json`、`progress.jsonl`、`artifact_manifest.json`、`SUCCESS.json`：输入、环境、进度和哈希；出错保存 `failure.json`。
- `--quick` 只读取已有冻结流/名义硬件/首批16条天气的三个时刻、模态0和10，共192对、17,280个模型单步样本，不产生新数据；状态固定 `QUICK_SMOKE_ONLY`。正式统计不能使用它替代。

验证结果与正式运行状态见[项目总览](项目总览.md)。旧B1源文件、模型及数据格式不改；本轮只新增独立诊断格式。
