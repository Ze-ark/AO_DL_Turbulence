# S4-D2-R2 闭环分布漂移诊断计划

## 先说结论

下一步不训练新模型，也不更换强化学习算法。我们只把已经训练好的四个模型放回动态仿真，检查它们为什么“做练习题时会答，自己连续控制时却失败”。

可以把上一阶段理解为：模型一直沿着老师走过的正确路线做题；本阶段则让模型自己开车。只要它前面一次动作有误，后面看到的场景就可能与训练时不同。我们要测量这种偏离是否存在、是否越积越大，以及把动作缩小后能否缓解。

## 为什么要做这一步

上一阶段得到两个看似矛盾的结果：

- 固定预见2帧的理想教师在闭环中使桶内功率提高`6.8875%`；
- 岭回归和三个多层感知机（MLP，一种普通前馈神经网络）在离线测试中能预测教师动作，但一放回闭环，桶内功率分别下降`52.1762%`、`39.2488%`、`41.4881%`和`32.1140%`。

因此现在不能直接说“观测不够”，也不能直接说“算法坏了”。必须先区分两种原因：

1. **动作过大**：预测方向大致正确，但误差经过连续累加后破坏闭环；
2. **闭环分布漂移**：模型自己的动作改变了后续状态，导致它遇到训练数据里很少见的输入，预测越来越不可靠。

## 具体做什么

冻结读取以下四个检查点，不更新参数：

- 岭回归；
- MLP种子8201；
- MLP种子8202；
- MLP种子8203。

每个模型的新增11维动作分别乘以`0%`、`10%`、`25%`、`50%`和`100%`。`0%`相当于只运行传统控制器，用来检查代码是否公平；其余档位用于观察缩小动作是否恢复性能。

正式诊断使用：

- 3种新动态条件：冻结流、带沸腾、带沸腾和变风及噪声；
- 6种硬件误差档位；
- 每个组合16个完整回合，每回合200步；
- 360条模型—缩放—条件场景记录、5760条逐回合记录；
- 另有传统基线和理想教师正对照；
- 总进度为396个场景，终端持续显示进度、桶内功率差和CUDA显存。

所有种子都是新的开发种子，不触碰后续强化学习和S4-D3保留种子。

## 重点看哪三个问题

### 1. 模型在自己产生的状态上还能不能看懂老师

每一步都用仿真真值计算理想教师动作，但这个真值只用于诊断比较，不送给学生模型。把闭环中的教师误差与上一阶段的离线误差相比：若早期和后期误差都达到离线误差的2倍，记为“学生状态与教师数据存在明显差距”。

### 2. 错误是否随时间累积

把200步分成5段，观察：

- 教师误差是否后期达到前期的1.5倍；
- 输入中超出训练分布3个标准差的比例是否增加至少2个百分点；
- 累计新增动作是否达到前期的1.25倍。

这些量共同变化，才更支持“越控制越偏”的解释。单独一个数异常时不能直接下结论。

### 3. 缩小动作是否能救回来

若某个小于100%的动作档位比100%档位至少提高5个百分点，记为动作幅度敏感。只有同时通过原科学门槛，才能称为“安全恢复”；仅仅少失败一点不算成功。

## 必须通过的完整性检查

- `0%`动作与传统基线的所有科学指标最大差不超过`5e-6`；
- 理想教师正对照必须通过；
- 请求动作、实际动作、投影比例和违规率分别记录；
- 四个检查点及上游数据、配置和审计记录的SHA256必须匹配；
- CUDA不可用时立即停止，不回退CPU；
- 不训练、不写检查点、不读取S4-D3、不连接真实SLM。

## 用户如何运行

在IDE集成终端进入仓库根目录，执行：

```powershell
.\.venv\Scripts\python.exe scripts\diagnose_s4_closed_loop_shift.py --config configs\experiments\s4_closed_loop_shift_v1.yaml
```

这不是训练，所以不会显示损失或保存新权重。正常时会看到：

```text
闭环分布漂移诊断:  已完成场景/396  功率差=...  显存=...GB
```

正式输出写入`outputs/s4_closed_loop_shift_v1`。运行结束后告诉助手“`闭环分布漂移诊断完成`”，由助手只读审计结果；不要自行重跑，也不要开始新RL训练。

## 结果怎样决定下一步

- **分布漂移得到支持，缩小动作仍不能恢复**：优先考虑闭环数据采集、迭代模仿学习或带历史记忆的策略，而不是盲目加训练轮数。
- **缩小动作可以通过原门槛**：先固定安全缩放并独立复验，再讨论RL是否有增量价值。
- **没有分布漂移，但所有缩放仍失败**：重新检查状态表示、教师标签和模型输出约束，再决定是否优化算法。
- **无论哪种结果**：在正式审计前，新RL、S4-D3和真实SLM都保持关闭。
