## 1. 小白版结论

S0 建好了一张正确的静态“练习题”。S1 现在让这张湍流相位屏随着时间被风吹动，并允许控制器每一帧调整一次补偿：

```text
当前观测
→ 请求十个低阶模态的变化量
→ SLM 延迟、量化和变化限制
→ 计算当前焦点好坏和奖励
→ 湍流继续移动
→ 得到下一观测
```

这已经是真正的时序控制环境，但还没有开始训练强化学习。

## 2. 当前环境到底看见什么

当前观测共有 22 个数：

```text
10个残余相位模态
+ 10个实际加载到SLM的模态
+ Strehl
+ 桶内功率
```

这些相位模态直接由仿真真值计算，相当于“标准答案传感器”。这样做是为了先把控制问题单独验证清楚。ResUNet 暂不接入；它将在控制基线稳定后作为感知模块加入。

## 3. 泰勒冻结流实现

严格冻结流假设下，相位屏形状不变，只按风速和风向做周期亚像素平移：

```text
每帧位移 = 风速 × 帧间隔
```

配置还保留 `frozen_flow_rho`：

- `1.0`：严格泰勒冻结流；
- 小于 `1.0`：在平移之外混入新的随机相位，模拟湍流“沸腾”或形变。

内部湍流屏为 256×256，控制器只观察中央 64×64。配置会拒绝一个回合内完整绕回的相位屏，避免控制器利用人工周期。

## 4. 动作与奖励

动作不是直接控制两百万个 SLM 像素，而是十个低阶实 Zernike 模态的增量。动作依次经过：

```text
模态范围 → 合成相位 → 相位范围 → 量化 → 帧延迟 → 单步变化限制
```

训练奖励当前由四部分组成：

```text
焦点质量
- 残余相位误差
- 动作幅度代价
- 越界或受限惩罚
```

奖励只是训练信号。正式比较仍要独立报告 Strehl、桶内功率、失败率和约束违规率。

验证内容包括：

5. 已知模态的反向动作提高 Strehl；

7. 焦面 FFT 保持能量；
8. 回合按设定步数终止；
9. 正式环境实际运行在 CUDA，没有静默回退 CPU；
10. MATLAB 与 PyTorch 对同一相位、位移和沸腾项给出相同结果。

## 6. GPU 冒烟结果边界

使用32个并行环境运行50步时，诊断性模态比例动作使平均 Strehl 从约 `0.452` 变为约 `0.758`。这个数字只证明动作链和评价方向正常：

- 它不是强化学习结果；
- 它不是调优后的传统基线；
- 它没有置信区间；
- 它不能用于论文算法排名。
