## 当前结论

R4-1A代码、配置、60项相关测试、CUDA小型冒烟及正式预检已完成。正式数据尚未采集，正式模型尚未训练。现在由用户在IDE启动一次采集与监督训练。

这一步可以理解为：先教模型回答“发出这条SLM命令后，下一帧会怎样变化”。还没有训练负责选择动作的RL（强化学习）策略。

R4-1分成两部分推进，本次只交付A：

1. **R4-1A**：完整回合采集、线性预测模型、线性模型加小型时序网络。
2. **R4-1B，尚未实现**：动作响应方向检验、可部署传统基座选择、共享预测模型的MPC（模型预测控制）闭环验证。

R4-1B通过前，不进入R4-2策略训练。这是实现拆分，不是降低原R4门槛。

## 你现在怎么运行

在项目根目录的IDE集成终端中运行一次：

```powershell
.\.venv\Scripts\python.exe scripts/train_s4_r4_dynamics.py --config configs/experiments/s4_r4_dynamics_v1.yaml
```

不需要手动生成数据，也不要加 `--quick`。程序依次执行采集、训练集归一化、线性拟合及正则选择、3个时序模型训练。终端显示每个阶段总批数、当前批次、模型1/3—3/3、累计平均损失、阶段预计剩余时间和CUDA显存。阶段间总量不同，进度条从0重新开始是正常的。

结果保存到 `outputs/s4_r4_dynamics_v1/`。完成后告诉助手“R4-1A训练完成”。如果报错，保留原报错和输出目录，不删除、不自行重跑。目录已存在时程序会拒绝覆盖，没有自动续跑或重试。

运行期间不要修改源码、冻结配置或来源清单。末端会重新检查哈希；修改代码会使本轮不能以完整来源通过验收。建议接通电源，避免电脑休眠。

## 数据与模型预算

| 项目 | 固定设置 |
|---|---|
| 独立训练天气 | 384条，3类各128条 |
| 开发选择天气 | 96条，3类各32条；与训练隔离，不是最终测试 |
| 每条天气 | 6个硬件档位 × 基座/受限激励2种采集器 × 200步 |
| 原仿真训练交互 | 921,600条转移 |
| 开发采集交互 | 230,400条转移，单独计数 |
| 基座参数 | gain=0.25，leak=0.10，tracking_gain=0.50；使用名义加载估计 |
| 激励动作 | 新增11维内均匀[-1,1]，保持4步再重抽；仍受原R4共享动作限制 |
| 观测历史 | 8帧，每帧79值及有效掩码 |
| 线性模型 | ARX（带动作输入的线性自回归），岭正则候选0.0001、0.01、1.0 |
| 非线性模型 | 冻结线性预测＋GRU（门控循环单元）残差，记忆宽度64，3个初始化 |
| 监督目标 | 未来1、2、4、8步的残余观测和对应动作功率，归一化误差等权 |
| 神经网络训练 | 每个模型10,000批，每批64个完整回合内片段；总30,000批 |
| 检查点 | 每500批开发检查；全部保留，最小平均归一化误差选择，平分取较早者 |

921,600是相邻状态转移数，不是921,600条独立天气。天气是拆分和重采样的基本单位：同一天气的全部硬件档位和采集器始终一起归属训练或开发集合。初始采集基座不是已经验证的最强基座，不复用旧含真实加载量的控制器或旧学生权重。

种子使用全仓库预扫描后空闲的376号块：训练从3760000、3760256、3760512开始，各128条；开发从3762048、3762304、3762560开始，各32条。冒烟另外使用3764096/3764352/3764608及3766144/3766400/3766656，每组2条。模型初始化为3769001—3769003。未使用378号A10块或4000000以上的S4-D3范围。

归一化统计只从训练集计算。输入尺度下限0.01，残余目标尺度下限0.02 rad，功率尺度下限0.001；模型输出残余增量和绝对功率。每个集合成员按完整天气重采样拟合线性模型并训练残差网络，保留同天气全部分支。

开发评估每条轨迹固定起点0、40、80、120、160，每次5,760个8步窗口。模型反复使用自己预测的残余和功率推进历史，命令序列来自记录；不会在每一步喂入下一帧真实观测。这属于给定命令的多步预测，不是闭环控制效果。

保持不变对照：残余保持最后一次观测，功率保持最后一次有效读数；回合起点无功率时使用训练集平均功率，不使用补零，也不使用开发标签估计初始值。总体误差和各时域两类误差都保存，不能只挑一个改善数字。

主要输出包括 `progress.jsonl`、`loss_history.csv`、`development_history.jsonl`、`data_manifest.json`、`linear_selection.json`、`training_normalization.pt`、`checkpoints/`、`artifact_manifest.json`、`summary.json` 和 `SUCCESS.json`。完整回合每批完成就更新清单，失败时已有轨迹仍保留；元数据用字节方式读取Git输出，避免Windows默认GBK解码再次破坏末端汇总。

## 实际验证（不是正式结果）

相关单元测试在小尺寸CPU上执行，不生成科学性能结果：

```powershell
.\.venv\Scripts\python.exe -B -m pytest -q tests/test_r4_dynamics.py tests/test_r4_interface.py tests/test_s1_env.py tests/test_s1_turbulence.py tests/test_s4_representation_capacity.py tests/test_runtime.py
```

最终结果：**60 passed**。其中包含：模型内名义延迟推进与R4-0接口逐帧一致；未来动作不能改变先前预测；动作到多步预测的梯度存在；回合末步不越界；真值字典不被加载；缺失功率不作为零功率对照。

CUDA冒烟已执行成功：12条独立天气，共144条完整回合、2,304条转移，3个模型各更新2批，6行损失、72份白名单轨迹、72份审计轨迹及12份检查点完整。166项产物哈希和SUCCESS摘要核对一致。它只验证软件链，不能排名模型。

冒烟输出：`outputs/s4_r4_dynamics_v1_quick/`，摘要SHA-256：`9e9eddd5e410a1f20b490f5468f5f251a13c2cb2889b27fa4b234fe4e2bd3dad`。

冒烟后发现并修订了“无初始功率时的保持模型”定义。原冒烟产物原样保留，不重写、不重训；最终代码与测试重新冻结。使用同一冒烟训练均值和开发轨迹在CUDA上只读复算，初始功率均值为0.6609153152，修订后保持模型的平均归一化误差为0.7277805209；原摘要中的保持模型分数已经过时，不能使用。此数值仍只是冒烟对照检查，不是正式性能结论。最终完整流程未再次重跑，已运行修订项单元测试和CUDA只读复算。

最终正式入口 `--preflight-only` 通过，状态为 `READY_FOR_USER_IDE`；正式输出目录不存在，尚未采集或训练。预检核对来源文件、上游R4-0验收及轨迹、CUDA、物理配置、259项历史配置/元数据和拆分隔离。

## 训练完成后的检查顺序

先核对来源哈希、全部数据与检查点、30,000行损失、60次开发检查和异常记录，再复算各时域预测误差。R4-1整体状态必须保持 `NOT_EVALUATED_ACTION_RESPONSE_AND_MPC_PENDING`，即使监督训练正常结束也不能自动放行RL。预测结果可用后再准备R4-1B，不自动重训、加数据或打开独立确认集。
