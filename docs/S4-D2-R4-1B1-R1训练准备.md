# R4-1B1-R1：动作差值监督训练准备

结论：代码、预检和小型CUDA冒烟已完成，可以由用户在IDE启动一次正式运行。正式采集和训练尚未开始，没有新的算法优劣结论。

## 这次具体做什么

让模型不仅学“接下来光功率是多少”，还专门学“加一次小动作后，比不加动作好多少”。从相同旧权重复制两组：对照组只学绝对预测；实验组再加动作前后的功率差目标。两组用相同训练数据、初始化和抽样序列，避免把多训练的好处误认为新目标的好处。

这仍是给后续模型式强化学习准备预测模型，不是强化学习策略训练，也还不是闭环补偿成功。

## 启动方式

在项目根目录的IDE集成终端运行一次：

```powershell
.\.venv\Scripts\python.exe scripts/train_s4_r4_delta_supervision.py --config configs/experiments/s4_r4_delta_supervision_v1.yaml
```

命令会先检查冻结文件，再采集训练配对，然后依次训练两组共6份模型。屏幕显示当前模型、总批数、当前批次、平均损失、剩余时间和CUDA显存；每500批开发评价期间会切换到评价进度条，不是卡住。

输出目录：`outputs/s4_r4_delta_supervision_v1/`。完成后应有 `summary.json` 和 `SUCCESS.json`。完成后告知助手“R4-1B1-R1训练完成”，再进行只读验收。若报错，保留原目录和报错，不删除目录、不重试、不续跑。

## 已批准的边界和预算

2026-09-09用户回复“继续”，确认前一轮提出的一次增补预算。原设计文档和 `s4_r4_delta_supervision_design_v1.yaml` 保留为审批前历史版本；本次批准及独立执行入口记录在 `s4_r4_delta_supervision_v1.yaml`。

- 复用96条既有训练天气，新采集410,112次物理仿真转移，得到38,016个动作配对；没有新增独立天气。
- 两组各3模型，每份固定2,000批，合计12,000批。两组都保留原轨迹预测损失和配对绝对预测损失，只有差值损失权重不同。
- 训练前向计算9,216,000个样本步；动作开发评价7,630,848个样本步。原轨迹开发预测另需1,105,920个样本步（1,152条开发回合×5起点×8步×24次评价）。这三类计算与物理仿真转移分开记账。
- 只训练门控循环网络（GRU）及输出层；原线性模型和归一化尺度不变。差值尺度由训练配对计算，开发数据不参与梯度、尺度或采样。
- 配对展开的后续动作只能由模型自己的预测生成，不使用D1诊断中的实际未来指令。实际动作与真值指标单独存审计文件，不进入训练输入。
- 最终2,000批权重是唯一主检查点，不挑开发最高分。需同时满足原动作方向门槛、相对同预算对照的配对区间门槛，以及3份模型的原8步预测门槛。开发天气已经多次使用，即便通过也不是独立确认。
