# R4-1B1：模型能否判断动作好坏

结论：程序、配置和小型检查已准备完成，正式诊断待用户在IDE运行。这次不训练模型，而是问它：“稍微这样调一下，接下来光功率会变好还是变坏？”通过后才准备模型预测控制（MPC）比较。


终端显示校准/诊断阶段、完成量、预计剩余时间和CUDA显存；持续保存 `progress.jsonl`。完成后告诉助手“R4-1B1诊断完成”，再只读验收结果。输出目录为 `outputs/s4_r4_action_response_v1/`；出现错误或目录已存在时保留现场，不删除、不自动重试。

## 检查什么

固定使用R4-1A选出的三份门控循环单元（GRU）预测模型，取三者预测变化量的平均值作为唯一主判据。线性模型和单个GRU只作辅助诊断，不能事后挑最好的一份宣布通过。

在同一仿真状态上复制分支，比较“正向微调、反向微调、零额外修正”。零修正不是停止补偿：各分支都继续运行同一个因果基础控制器。每次只在第一步给一个高阶模态额外修正，之后7步额外修正归零，比较8步平均测量功率与零修正分支之差。

物理分支使用各自随后获得的带噪观测；模型分支使用各自预测出来的后续观测计算控制指令。不能把实际未来指令、真实相位、真实已加载状态或隐藏硬件档位喂给模型。各动作配对复制相同随机状态，以减少无关噪声差异。

## 固定预算与统计门槛

| 项目 | 正式设置 |
|---|---|
| 噪声校准 | 复用48条训练天气，每类16条；不训练模型 |
| 动作方向开发检查 | 复用R4-1A的96条开发天气，每类32条；不是新独立确认 |
| 环境 | 3类天气、6个硬件误差档位 |
| 探针时刻 | 第0、80、160步 |
| 动作 | 11个新增高阶模态，每个正负两方向，另有共享零修正分支 |
| 物理转移 | 校准59,904条，开发410,112条，总计470,016条 |
| 动作配对 | 38,016对，但仍只有96条独立开发天气 |
| 模型计算 | 1,907,712个单样本单步预测；模型更新0次 |

噪声阈值只从训练天气确定：复制零修正分支，仅更换功率测量噪声，保持物理轨迹和指令完全一致；按硬件档位计算重复测量差值的标准差，阈值取其3倍，数值下限为 `1e-7`。阈值在开发检查前写盘并锁定，不看开发结果调整。

只有功率变化绝对值超过该阈值的配对才进入方向准确率计算，但全部原始配对仍保存。这里的信号筛选只用于方向可辨识性检查，不能用于以后筛除闭环表现差的回合。

原定通过门槛不变：

- 有效信号覆盖至少50条开发天气，且存在改善和恶化两类动作；
- 平衡准确率至少60%：分别计算“变好”和“变坏”的判断正确率，再取平均，避免只猜多数类；预测恰为零算判断错误；
- 按天气整体、在天气类型内分层重采样20,000次，95%区间下界严格大于50%。同一天气的模态、时间和硬件档位不能当成互相独立样本；无效区间不能放行。

信号不足返回 `INSUFFICIENT_SIGNAL`；有信号但未过准确率或区间门槛返回 `ACTION_DIRECTION_FAIL`。通过也只表示这一类小修正的方向判断达标，不意味着任意动作、规划器或强化学习有效。
