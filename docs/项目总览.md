# 项目总览

本项目研究离轴数字全息观测下的自适应光学补偿。当前主线不是直接在真实 SLM 上训练强化学习，而是：

```text
修复纯仿真 → 建立动态闭环 → 做强传统基线 → 测试 RL 的额外价值
→ 加入真实硬件误差 → 双 SLM 影子测试与硬件在环 → 独立物理扰动
```

## 必用研究技能

本项目所有任务必须先使用已注册的 `academic-research-suite`：完整读取入口 `SKILL.md`，再根据任务只进入一个匹配的工作流，不允许静默跳过，也不应一次性加载整个技能库。

常用路由如下：

| 项目任务 | 使用的工作流 |
|---|---|
| 实验设计、运行、基准测试、结果统计和复现 | `experiment-agent` |
| 文献调查、研究问题和事实核查 | `deep-research` |
| 论文大纲、写作、修改和引用检查 | `academic-paper` |
| 同行评审与审稿意见模拟 | `academic-paper-reviewer` |
| 从研究到论文的完整管线 | `academic-pipeline` |

普通代码修改和调试也必须先加载技能入口，但只在任务确实匹配时读取内部工作流。技能不可用时应停止并报告。使用技能不会自动授权联网、外部模型、真实SLM操作或多智能体；这些仍服从用户授权和仓库安全规则。项目文档继续使用UTF-8简体中文。

## 两条并行路线

### 电脑端：纯仿真主线

1. `S0`：修复传播、相位屏、接收面参考和评价指标；
2. `S1`：建立“观测 → 动作 → 下一观测”的动态环境；
3. `S2`：完成直接相位补偿、积分器、LQG/MPC 等传统基线；
4. `S3`：条件满足时比较同模型 MPC、PO4AO 式策略和残差 SAC；
5. `S4`：加入噪声、延迟、量化、饱和、LUT 偏差和配准误差；
6. `S5`：冻结策略后进入真实系统影子测试。

### 实验室端：双 SLM 标定

1. `H0`：查清两台 SLM、激光器、相机和功率计探头的信息；
2. `H1`：分别测量两台 SLM 的灰度—相位关系、稳定时间和空间校正；
3. `H2`：不用 RL，先证明 SLM-A 制造的已知扰动能被 SLM-B 稳定抵消；
4. `H3`：测量真实动作—响应时序，并判断系统是否存在可利用的动态规律。

纯仿真和 H0—H1 可以并行推进。H1 的实测参数以后用于替换仿真中的假设范围。

## 算法怎么选

算法不按名字预先锁定：

- 没有时间规律：不做 RL，使用静态校正；
- 线性模型已经足够：优先使用 LQG 或 MPC；
- 非线性模型稳定优于线性模型：比较“同一非线性模型 + MPC”和“同一模型 + PO4AO 式策略”；
- 残差 SAC 作为第二 RL 候选；
- PPO 先只做纯仿真补充。

RL 必须在相同观测、动作约束、训练数据和测试扰动下，与强传统方法公平比较。

## 现有静态模型

当前 ResUNet 输入为：

```text
[normalized_intensity, wrapped_phase]
```

输出为：

```text
phi_corr
```

现有代码使用：

```text
E_comp = E_turb * exp(-1j * phi_corr)
```

这一流程保留为静态基线和软件冒烟测试，但它不是动态闭环，也不能单独证明焦平面性能改善。

## 数据分工

| 数据 | 用途 | 禁止外推的结论 |
|---|---|---|
| 当前静态仿真 HDF5 | 软件冒烟、静态基线 | 不能作为正式 AO 或 RL 结果 |
| 修复后的动态仿真轨迹 | 传统控制和 RL 的训练、验证、测试 | 不能直接代表实际 SLM |
| 现有真实复光场 HDF5 | 真实域检查、重建流程验证 | 没有动作响应，不能训练闭环 RL |
| 双 SLM 动作—响应轨迹 | 系统辨识、影子测试、硬件在环评价 | 数字相位屏仍不等同自然大气 |

## 现有程序入口

下面三个入口目前只属于静态原型流程：

```powershell
.\.venv\Scripts\python.exe -m src.train_compensation --config configs\sim_gaussian_v1.yaml
.\.venv\Scripts\python.exe -m src.evaluate_compensation --config configs\sim_gaussian_v1.yaml
.\.venv\Scripts\python.exe -m src.validate_real_experiment --config configs\sim_gaussian_v1.yaml
```

`configs/sim_gaussian_v1.yaml` 已标记为 `s0_static_physics_validation`。它不属于动态控制器比较。

S1 动态环境已经有独立入口：

```powershell
.\.venv\Scripts\python.exe scripts\run_s1_smoke.py --steps 50
```

它运行的是诊断用模态比例动作，不是 SAC、PO4AO 或正式传统基线。

S2 统一观测、ResUNet 与最终封存比较：

```powershell
.\.venv\Scripts\python.exe scripts\check_s2_resunet_transfer.py
.\.venv\Scripts\python.exe scripts\train_s2_dynamic_resunet.py
.\.venv\Scripts\python.exe scripts\run_s2_baselines.py --final
```

旧静态权重不能直接适应理想瞳面观测；重新训练的动态无记忆 ResUNet 通过感知测试，但在最终封存闭环比较中没有超过泄漏积分器和线性预测器。详细结果见 `docs/S2传统基线验证记录.md`。

S3 多帧动力学门槛训练由用户在 IDE 中运行：

```powershell
.\.venv\Scripts\python.exe scripts\train_s3_dynamics.py --config configs\experiments\s3_dynamics_v1.yaml
```

该命令让 GRU 与使用相同 8 帧历史和相同数据的线性岭回归公平比较；它只生成训练和验证回合，不生成或评估封存回合，也不是强化学习。训练结束后先让助手读取结果。详细设计见 `docs/S3非线性动力学门槛计划.md`。

原 S3 验证门槛已经失败。为了判断是否由数据量或模型过大造成，用户在 IDE 运行独立学习曲线诊断：

```powershell
.\.venv\Scripts\python.exe scripts\train_s3_data_scaling_diagnostic.py --config configs\experiments\s3_data_scaling_diagnostic_v1.yaml
```

它使用新的开发种子，不触碰原 S3 封存测试。详细设计见 `docs/S3数据量诊断计划.md`。
